# 아이콘 · UI 디테일 — 고급스러움이 드러나는 작은 부분의 실제 값 (KOSAI 용)

> 조사일 2026-09-26. 1차 출처(디자인 시스템 원본 토큰·소스 파일, 공식 브랜드 가이드, W3C, NN/g, Baymard)를 우선했다.
> **자체 실측** 표시는 이 조사에서 직접 잰 값이다. 2026-09-26 에 linear.app · vercel.com · stripe.com · toss.im · tossinvest.com · mercury.com · ft.com · apple.com 첫 페이지 HTML 과 거기 걸린 CSS(사이트당 최대 14개)를 받아 선언값을 셌다. JS 가 나중에 넣는 스타일은 빠지므로 "CSS 에 박아 둔 값"으로만 읽어야 한다. bloomberg.com 은 봇 차단으로 본문을 못 받았다.
> **계산** 표시는 공개 수치로 직접 계산한 값(대비비·렌더 선 굵기), **추정**은 근거가 간접적인 값이다.
> 이미 있는 헌장(`docs/design/KOSAI-design-charter.md` 4.1·4.11·4.12)과 겹치는 곳은 헌장 값을 확인·보정하는 쪽으로 썼다.

## 1. 아이콘 — 세트, 선 굵기, 광학 크기, 라이선스, 글자와의 정렬, 금융 기호

### Takeaway
주요 무료 세트는 모두 24px 격자·둥근 끝이지만 **기본 선 굵기가 다르다**: Lucide·Tabler 2px, Heroicons outline 1.5px, Phosphor Regular 1.5px 상당(24px 표시 기준). "인쇄된 리포트" 톤과 Pretendard 본문에는 **1.5px 계열**이 맞는다. 고급스러움을 가르는 것은 세트 선택보다 **렌더된 선 굵기를 크기와 상관없이 한 값으로 맞추는 것**이고, 지금 스테이징은 이 값이 1.17~1.75px 로 흩어져 있다(계산, 아래).

### Cited Findings
**세트별 원본 규격**
- Lucide: 24×24 캔버스, 선 2px, 둥근 이음·끝, 가장자리 여백 1px 이상, 8px 이상 도형의 모서리 반경 2px(작은 도형 1px), 요소 사이 2px 이상 — [Lucide Icon Design Guide](https://lucide.dev/contribute/icon-design-guide). 원본 SVG `lock.svg` 도 `stroke-width="2"`, `stroke-linecap/linejoin="round"` — [lucide/icons/lock.svg](https://github.com/lucide-icons/lucide/blob/main/icons/lock.svg). 라이선스 ISC — [Lucide LICENSE](https://github.com/lucide-icons/lucide/blob/main/LICENSE)
- Heroicons: 24 outline · 24 solid · 20 solid · 16 solid 네 벌, MIT — [heroicons README](https://github.com/tailwindlabs/heroicons). 24 outline 원본 SVG 는 `stroke-width="1.5"` · 둥근 끝(자체 실측, `optimized/24/outline/lock-closed.svg`) — [lock-closed.svg](https://github.com/tailwindlabs/heroicons/blob/master/optimized/24/outline/lock-closed.svg)
- Tabler: 24×24, `stroke-width="2"`, 둥근 끝(자체 실측, `icons/outline/lock.svg`), MIT — [tabler-icons](https://github.com/tabler/tabler-icons)
- Phosphor: 1,248+개, Thin·Light·Regular·Bold·Fill·Duotone 여섯 무게, "16×16px 에서 설계", MIT — [phosphor-icons/homepage](https://github.com/phosphor-icons/homepage). 원본은 256 viewBox 채움 경로다. `lock` 의 몸통 테두리 두께가 Thin 8 · Light 12 · Regular 16 · Bold 24 단위(자체 실측) → 24px 표시 때 **0.75 · 1.125 · 1.5 · 2.25px**(계산) — [phosphor-icons/core assets](https://github.com/phosphor-icons/core)
- Material Symbols: 가변 축 FILL 0–1, 무게 100–700, Grade −50–200, 광학 크기 20–48dp. 기본값 무게 400·opsz 48·grade 0. 어두운 바탕의 밝은 아이콘은 **grade −25** 로 번짐을 줄이라고 권한다. Apache 2.0 — [Material Symbols guide](https://developers.google.com/fonts/docs/material_symbols)
- SF Symbols: 아홉 무게(ultralight~black)가 San Francisco 글꼴의 무게와 하나씩 대응해 "인접 글자와 정확한 무게 맞춤"을 하게 하고, 세 스케일(small·medium·large)은 **SF 글꼴의 캡하이트 기준**으로 정의된다 — [Apple HIG SF Symbols](https://developer.apple.com/design/human-interface-guidelines/sf-symbols). 7,000개 이상 — [Apple SF Symbols](https://developer.apple.com/sf-symbols/)
- Vercel Geist 아이콘: vercel.com 헤더의 아이콘은 `viewBox="0 0 16 16"` 채움(fill) 경로를 14px 로 표시(자체 실측, vercel.com HTML `data-slot="geist-icon"`) — [vercel.com](https://vercel.com/)
- Pretendard: 아홉 굵기 + 가변 글꼴, Inter · 본고딕 · M PLUS 1p 를 합친 글꼴, SIL OFL — [Pretendard](https://github.com/orioncactus/pretendard)

**글자 옆 아이콘**
- 스테이징(자체 실측, `comp_common.py`): 단추 안 아이콘 16px·stroke 2, '더보기' 14px·2, 가림창 자물쇠 30px·1.4, 모두 viewBox 24 → **렌더 1.33 · 1.17 · 1.75px** 로 제각각(계산: stroke × 크기 ÷ 24).
- Linear 단추 토큰은 아이콘 크기를 단추 크기와 함께 올린다: 24px 단추 12px 아이콘·간격 4px, 32/40px 단추 16px·간격 8px, 40(default)/44px 단추 18px·간격 6px(자체 실측, linear.app CSS `--button-icon-size`·`--button-gap`) — [linear.app](https://linear.app/)
- Primer 는 컨트롤 간격(gap) 4px(xsmall·small) / 8px(medium 이상) — [primer/primitives size.json5](https://github.com/primer/primitives/blob/main/src/tokens/functional/size/size.json5)

**아이콘만 vs 글자만**
- Apple: "아이콘보다 짧은 글자가 더 분명하면 글자를 쓰라", 단추 이름은 동사로 시작("Add to Cart") — [Apple HIG Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)
- 이름 없는 아이콘에는 툴팁이 필요하다 — [NN/g Tooltip Guidelines](https://www.nngroup.com/articles/tooltip-guidelines/). Primer 는 툴팁을 "IconButton 의 이름을 보여 주는 데만" 쓰라고 한다 — [Primer Tooltip](https://primer.style/product/components/tooltip/guidelines/)

**금융 기호(▲▼ · 셰브론 · ↗)**
- 한국거래소·넥스트레이드는 상승 빨강·하락 파랑을 쓰고, 거래소는 "바꾸기가 쉽지 않을 것"이라며 변경 계획이 없다고 했다(2025-10). 하나은행 딜링룸은 2024년 이후 상승을 녹색으로 바꿨다 — [아시아타임즈 2025-10-10](https://www.asiatime.co.kr/article/20251010500293)
- Vercel 은 외부 링크 표시로 `↗` 를 글자 뒤 `margin-left:0.125em` 에 붙인다(자체 실측, vercel.com 헤더 'v0 ↗') — [vercel.com](https://vercel.com/). 즉 ↗ 는 웹에서 이미 '밖으로 나감' 뜻으로 쓰인다.
- 토스 기업 사이트 CSS 에 `#3182f6`(파랑) 60회, `#f04452`(빨강) 28회(자체 실측, toss.im). tossinvest.com 첫 페이지 CSS 에는 등락 색·▲▼ 문자가 없었다(JS 로 그려서 측정 불가).

### Inferences
- 1.5px 계열(Heroicons outline · Phosphor Regular · Lucide 를 1.5 로 내린 것)이 Pretendard 400–500 본문과 무게가 맞는다(추정 — Pretendard 획 두께를 직접 재지는 않았다). 2px(Lucide·Tabler 기본)는 13–15px 본문 옆에서 글자보다 진해 '앱 UI' 인상이 난다.
- 가장 싸게 품질을 올리는 방법: 한 세트(Lucide 형태 + 선 굵기만 조정)로 통일하고, SVG 에 `vector-effect:non-scaling-stroke` 를 주어 **CSS px 기준 1.5px 로 고정**하면 14·16·20·24px 어디서나 같은 굵기로 보인다. 크게 쓰는 빈 상태 아이콘(40px)만 1.75px.
- 광학 정렬: 글자 옆 아이콘은 글자 크기의 1.1–1.25배(15px 글자 → 16–18px), 간격 6px(글자 15–16px) / 8px(단추 40px 이상). 세로는 `align-items:center` 보다, 캡하이트 기준으로 1px 내리는 편이 한글에서 가운데로 보인다(추정 — 한글은 라틴보다 글자 몸이 커서 기하 중심이 위로 뜬다).
- 등락 기호: 표·셀 안은 **부호(+/−)와 색**만, 헤더·요약 줄에만 ▲▼(U+25B2·U+25BC)를 0.7em 로. ↗↘ 는 외부 링크 뜻과 겹치므로 등락에 쓰지 않는다. 셰브론(›, ⌄)은 '펼치기·다음 단계' 전용.

### Gaps
- SF Symbols 약관 원문(웹 사용 가능 여부)은 받지 못했다. 웹 사용이 막혀 있다고 널리 알려져 있으나 미확인 — KOSAI 는 쓸 이유도 없다.
- Pretendard 400/500 의 실제 획 두께(px)와 아이콘 1.5px 의 시각 무게 비교는 측정하지 않았다(렌더 캡처 필요).
- 토스증권·네이버증권의 실제 등락 표시 문자(▲ 인지 삼각형 SVG 인지)는 JS 렌더라 확인하지 못했다.

## 2. 단추 — 높이, 모서리, 여백, 글자, 상태, 로딩, 아이콘 단추

### Takeaway
고급 제품들의 단추 높이는 **32 · 40 · 44 · 48px** 네 칸에 몰린다. 마케팅 주 단추는 44–48px, 제품 UI 는 32–40px. 모서리는 알약(Linear 일부·Geist rounded)과 **거의 직각(Stripe 4px·2px)** 두 갈래로 갈리고, 둘 다 고급으로 읽힌다 — 중요한 건 한 사이트 안에서 한 가지로 일관되는 것이다. 로딩은 **폭을 그대로 두고 안에서** 보여 준다(Geist·TDS·Apple 공통).

### Cited Findings
**높이·글자·여백(원본 토큰)**
- Linear(자체 실측, CSS 모듈 `S36ykG_size-*`): mini 24px·12px 글자·좌우 10px / small 32px·13px·12px / medium 40px·13px·14px / default 40px·**15px**·16px / large **44px·16px·20px**. 모서리 토큰은 `--radius-4` 또는 `--radius-rounded`(알약) — [linear.app](https://linear.app/)
- Stripe(자체 실측, `.hds-button`): 글자 1rem·굵게·line-height 1, 위 15.5 / 아래 16.5px → **48px**, 기본 13.5/14.5 → **44px**, compact 11.5/12.5 → 40px. **아래 여백을 1px 더 주어 광학 중심**을 맞춘다. 모서리 `--hds-space-button-radius-lg` = 4px, `-sm` = 2px — [stripe.com](https://stripe.com/)
- Vercel Geist(자체 실측, vercel.com CSS): `--geist-form-small-height` 32px · `--geist-form-height` 36px · `--geist-form-large-height` 40px, `--geist-radius` 6px, `--geist-marketing-radius` 8px — [vercel.com](https://vercel.com/) (구버전 토큰이 남아 있는 것일 수 있다 — 추정)
- Geist 문서: small·medium(기본)·large, `shape="rounded"` 는 "마케팅 페이지에서 자주 쓴다", 아이콘만인 단추는 `svgOnly` + `aria-label` 필수 — [Geist Button](https://vercel.com/geist/button)
- GitHub Primer: xsmall 24 · small 28 · medium 32 · large 40 · xlarge 48px, 세로 여백 2/4/6/10/14px, 좌우 condensed 8 · normal 12 · spacious 16px, 최소 터치 타깃 fine 16px / **coarse 44px** — [primer/primitives size.json5](https://github.com/primer/primitives/blob/main/src/tokens/functional/size/size.json5), [Primer ButtonBase CSS](https://github.com/primer/react/blob/main/packages/react/src/Button/ButtonBase.module.css)
- 토스 TDS Mobile: small·medium·large·xlarge, fill(채도 높음)·weak(채도 낮음), 색 primary·dark·danger·light, display inline·block·full. px 값은 문서에 없다 — [TDS Mobile Button](https://tossmini-docs.toss.im/tds-mobile/components/button/). toss.im CSS 에서 높이 28·32·48px, 모서리 6·8px 가 보였으나 표본이 적다(자체 실측, 약한 근거).

**터치 크기**
- Apple: 단추 히트 영역 최소 **44×44pt** — [Apple HIG Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)
- WCAG 2.2 SC 2.5.8(AA): 타깃 최소 **24×24 CSS px**, 작으면 24px 원이 겹치지 않을 간격. 문장 안 링크는 예외. 중요한 컨트롤은 2.5.5(강화)를 노리라 — [W3C Understanding 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

**상태**
- Apple: "커스텀 단추에는 항상 눌림 상태를 넣어라. 없으면 입력을 받는지 의심하게 된다." 파괴적 동작은 시스템 빨강, 주(primary) 역할은 파괴적이지 않은 단추에 — [Apple HIG Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)
- 로딩: Apple — 곧바로 끝나지 않는 동작은 단추 안에 활동 표시기 — [Apple HIG Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons). Geist — "스피너로 바꿔 끼우지 말고 `loading` 을 넘겨 단추가 포커스를 유지하고 보조기기에 busy 를 알리게 하라" — [Geist Button](https://vercel.com/geist/button). TDS — "로딩 중에는 3개의 인디케이터가 순차적으로 움직이며, 버튼의 너비는 변하지 않아요" — [TDS Mobile Button](https://tossmini-docs.toss.im/tds-mobile/components/button/)
- 비활성: Geist — 동작이 "지금 불가능할 때만"(입력 누락·권한 없음) 비활성, **왜 안 되는지 툴팁**과 짝 — [Geist Button](https://vercel.com/geist/button)
- 포커스 링(자체 실측): Vercel `0 0 0 2px 바탕색, 0 0 0 4px 포커스색`(이중 링) / Apple `2px solid #0071e3`, offset 1px(컨테이너 3px) / 토스 `inset 0 0 0 1.5px #3182f6, 0 0 0 2px #e8f3ff` / Mercury `outline-width:2px` — [vercel.com](https://vercel.com/), [apple.com](https://www.apple.com/), [toss.im](https://toss.im/), [mercury.com](https://mercury.com/)
- 커서: Tailwind v4 는 단추 기본 커서를 `pointer` → `default` 로 바꿨다("브라우저 기본 동작에 맞춤") — [Tailwind v4 Upgrade Guide](https://tailwindcss.com/docs/upgrade-guide). Stripe `.hds-button` 은 `cursor:pointer` 유지(자체 실측).

**스테이징 현재값(자체 실측, `scripts/comp_common.py`)**
- `.btn` 40px · 알약 999px · 600 14px · 좌우 18px · hover `opacity:.9`. 로그인 가림창 `.kg-btn` 48px · 600 15px · 1px `--line` 테두리. 모바일 전폭 `.btn` 44px.
- ink `#141414` 단추의 90% 불투명 = `#2b2b2b`, 그 위 `#f9f8f6` 글자 13.34:1(계산) — hover 대비는 충분하다.

### Inferences
- KOSAI 는 알약이 이미 대표 결정이므로 **알약 한 가지**로 가고, 높이는 **40(보조·헤더·인라인) / 48(주 CTA·폼 제출·가림창)** 두 칸만 둔다. 44 는 모바일 전폭에만 쓰고 있는데 48 로 합치면 칸이 하나 준다(Stripe 44/48, Primer xlarge 48, Linear large 44 가 근거). 헌장 4.x 의 "알약형 CTA 금지" 문장은 현재 방향(먹색 알약 허용)과 어긋나니 헌장 쪽을 고쳐야 한다.
- 글자: 40px → 14px/600, 48px → 15–16px/600. Linear 가 한 단계 큰 단추에서 글자를 13 → 15 → 16 으로 같이 올리는 것이 '고급 비율'이다. 한글 600 은 라틴 600 보다 진해 보이므로 500–600 사이에서 실기기 확인(추정).
- Stripe 식 **아래 +1px 여백**은 Pretendard 에서도 필요할 가능성이 높다 — 한글은 기준선 위로 몸이 크게 올라가 `line-height:1` 가운데 정렬 때 약간 높아 보인다(추정, 캡처로 확인 필요).
- hover 는 `opacity` 보다 **배경색 교체**(ink → `#2b2b2b`)가 낫다 — opacity 는 글자까지 옅게 만들고, 아이콘·스피너도 같이 흐려진다(추론). outline 알약 hover 는 배경 `rgba(20,20,20,.04–.06)`.
- 눌림(active)은 배경 한 단계 더(`#000` 또는 `#3a3a3a`)만, 크기 변화 없이. 움직임 규칙은 06번 노트를 따른다.
- 아이콘만인 단추(테마·햄버거·☆): 보이는 원 36–40px, 히트 영역 44px(`::before` 로 확장), `aria-label` 필수, 데스크톱에서만 툴팁.

### Gaps
- Material 3 단추 사양 페이지는 JS 렌더라 본문을 받지 못했다(M3 높이·모양 값 미확인).
- 토스 TDS 의 단추 px 값은 공개 문서에 없다. Linear 의 `--radius-4` 실제 px 도 CSS 에서 풀리지 않았다.

## 3. 폼 — 입력칸, 라벨, placeholder, 오류·성공, 자동완성, 한글 IME, 비밀번호, 소셜 로그인

### Takeaway
라벨은 **칸 위에 항상 보이게**, placeholder 는 예시로만. 검사는 **칸을 떠날 때(blur)** 하고, 고치는 순간(키 하나) 오류를 지운다. 한국 사이트는 **IME 조합 중 Enter**를 반드시 막아야 한다. 소셜 로그인은 각 브랜드 규칙(색·로고·문구)을 지키되 **셋을 같은 크기로** 세운다 — 구글·카카오 모두 "다른 버튼보다 덜 눈에 띄게 하지 말라"고 명시한다.

### Cited Findings
**라벨·placeholder**
- placeholder 가 해로운 일곱 이유(기억 부담, 검토 불가, 오류 수정 어려움, 탭 이동 시 못 봄, 채운 칸이 덜 보임, 기본값으로 오인, 지우는 수고). "기본 밝은 회색 placeholder 는 대부분 바탕에서 대비가 낮다." 라벨·힌트는 칸 **밖에** 항상 보이게 — [NN/g Placeholders](https://www.nngroup.com/articles/form-design-placeholders/)

**오류·검사 시점**
- Baymard(2024-01-09): 사이트의 31% 가 인라인 검사가 없고 4% 는 잘못 구현. 사용자가 입력을 시작하기 전에 검사하지 말 것, **onblur** 에 검사, 우편번호·전화·카드처럼 길이가 정해진 칸은 길이가 찼을 때 검사, 오류는 **고친 키 입력 즉시** 사라져야 한다, 초록 체크 같은 **긍정 인라인 검사**가 신뢰를 준다 — [Baymard Inline Validation](https://baymard.com/blog/inline-form-validation)
- NN/g(2023-05-14): 오류는 발생 자리 가까이, 굵게·고대비·빨강 등 **중복된** 표시, 색에만 의존하지 말 것, 입력값 보존, "invalid/illegal" 같은 말 금지, 해결책 제시, 실시간 검사는 오류가 잦은 칸에만 — [NN/g Error Message Guidelines](https://www.nngroup.com/articles/error-message-guidelines/)

**높이**
- Primer 컨트롤(입력·선택 포함) 24/28/32/40/48px, coarse 포인터 최소 44px — [primer/primitives size.json5](https://github.com/primer/primitives/blob/main/src/tokens/functional/size/size.json5). Geist 폼 높이 토큰 32/36/40px(자체 실측) — [vercel.com](https://vercel.com/)

**한글 IME**
- `KeyboardEvent.isComposing` 은 `compositionstart` 뒤 `compositionend` 전에 발생한 키 이벤트면 true — [MDN isComposing](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/isComposing)

**소셜 로그인 브랜드 규칙**
- Google: 라이트 채움 `#FFFFFF` · 테두리 `#747775` 1px 안쪽 · 글자 `#1F1F1F`; 다크 `#131314` · `#8E918F` · `#E3E3E3`; 뉴트럴 `#F2F2F2` 테두리 없음. 글꼴 Google Sans Medium **14/20**. 웹 여백: 로고 앞 12px · 로고 뒤 10px · 글자 뒤 12px. 문구 "Sign in / Sign up / Continue with Google"(현지화 권장). G 로고 크기·색 변경 금지. "다른 제3자 로그인 옵션**만큼 이상** 눈에 띄게" — 대략 같은 크기·비슷한 시각 무게 — [Google Sign-In Branding](https://developers.google.com/identity/branding-guidelines)
- Kakao: 컨테이너 `#FEE500`, 심볼 `#000000`, 레이블 `#000000` 85%, **모서리 12px**, 문구 "카카오 로그인"(축약 "로그인"), 심볼은 왼쪽 정렬 또는 레이블과 함께 가운데. 금지: 규정 밖 색, "타사 로그인 버튼을 강조해서는 안 됩니다", 심볼 변형, 심볼 없이 구성 — [Kakao 로그인 디자인 가이드](https://developers.kakao.com/docs/ko/kakaologin/design-guide)
- Naver: Naver Green `#03C75A`(RGB 3/199/90). 크게 키울 땐 비율 유지, 레이블 세로 길이는 컨테이너 세로의 1/3 이하, 작으면 축약형 '로그인', 다크 모드 버전 제공 — 검색 요약 기준(developers.naver.com 은 이 환경에서 접속 차단) — [네이버 로그인 BI](https://developers.naver.com/docs/login/bi/bi.md); 같은 그린 `#03C75A` 는 네이버 클라우드 가이드에서도 확인 — [NCloud 로그인 버튼 가이드](https://guide.ncloud-docs.com/docs/sso-button-design-guide)
- 대비(계산): 카카오 레이블(검정 85%) on `#FEE500` = 12.52:1. 흰 글자 on `#03C75A` = **2.25:1** — 글자라면 WCAG AA(4.5:1) 미달이지만 브랜드 규정 요소다.

**자동완성 · 비밀번호 보기**
- 이번 조사에서 1차 출처를 확보하지 못했다(Gaps).

### Inferences
- KOSAI 입력칸: 높이 **48px**(모바일·데스크톱 같게 — 가입·로그인은 드물게 쓰는 폼이라 여유가 품질로 읽힌다), 모서리 **8px**(알약은 단추 전용으로 남겨 역할을 구분), 테두리 ink **48% 이상**(`#8b8b8a`, 3.21:1 — WCAG 1.4.11 비텍스트 3:1, 계산). 40% 는 2.56:1 로 미달(계산).
- 라벨: 칸 위 8px, 14px/500 ink 72%(7.14:1). placeholder 는 예시만('name@example.com'), ink **60% 이상**(4.72:1) — 기본 회색은 미달하기 쉽다.
- 오류: 칸 아래 6px, 13px, 글자는 ink + '오류:' 접두 + 작은 아이콘, 칸 테두리만 `--err`(헌장 4.x 와 같음). 성공 체크는 **이메일 형식·비밀번호 규칙 충족**처럼 사용자가 불안한 칸에만.
- 한글 IME: 검색창·폼의 Enter 처리에 `if (e.isComposing || e.keyCode === 229) return;` 을 넣는다. 조합 중 Enter 로 마지막 글자가 두 번 들어가거나 조합 전 문자열로 검색되는 문제가 한국 사이트의 흔한 '만들다 만' 신호다(추론 — 229 는 IME 처리 중 키코드로 널리 쓰이는 관례값이며 이번에 원문 확인은 못 함).
- 자동완성: 크롬의 파랑/노랑 배경이 회백 바탕에서 튄다 → `:autofill` 에 `box-shadow:inset 0 0 0 100px var(--bg)` + `-webkit-text-fill-color:var(--ink)`(통상 해법, 출처 미확보).
- 비밀번호 보기: 칸 안 오른쪽 글자 단추 '보기/숨기기' 13px — 눈 아이콘보다 뜻이 분명하다(추론, Apple 원칙 적용).
- 소셜 로그인: 세 단추 **같은 높이 48px · 같은 폭 · 세로로 쌓기 · 간격 10–12px**. 카카오가 모서리 12px 를 요구하므로 **소셜 단추 셋은 모두 12px 둥근 사각**으로 맞추고, KOSAI 자체 동작(알약)과 모양으로 구분한다 — 남의 브랜드 단추와 우리 단추가 섞여 보이지 않는 효과도 있다(추론). 순서에 대한 공식 규칙은 찾지 못했다. 한국 사용자 분포상 카카오 → 네이버 → 구글이 흔하나(추정), 구글은 "덜 눈에 띄게" 만 금지하므로 순서 자체는 자유다.

### Gaps
- `:autofill` 스타일링, 비밀번호 보기 토글, 229 키코드는 1차 출처(MDN·Baymard)를 이번에 받지 못했다.
- 네이버 로그인 가이드 원문(레이블 색·모서리·높이)은 접속 차단으로 확인 못 했다. 러너(Actions)에서 받아 확인할 것.
- 구글 GIS 렌더 단추의 높이(large/medium/small)는 이번 페이지에 없었다.

## 4. 링크와 글자 UI — 밑줄, 외부 링크 표시, 눈썹, 절 번호, '기준 시각'

### Takeaway
고급 사이트의 본문 링크는 **얇은 밑줄(1–1.5px) · 글자와 2.5–4px 띄움 · 밑줄 색은 글자보다 옅게** 가 공통이다. hover 에서 밑줄이 진해지거나 사라진다. 외부 링크는 글자 뒤에 작은 ↗ 하나.

### Cited Findings
- Linear(자체 실측): `text-decoration-thickness:1.5px` 57회, `text-underline-offset:2.5px` 57회, 밑줄 색 `var(--color-text-quaternary)`(가장 옅은 글자색) 60회 — [linear.app](https://linear.app/)
- Vercel(자체 실측): offset 4px(5회)·2px(3)·5px(2), thickness 1px, 밑줄 색 `--ds-gray-500` 20회. 헤더 링크는 평소 밑줄 없음 → hover·현재 페이지일 때만 `decoration-1 underline-offset-[5px]` — [vercel.com](https://vercel.com/)
- Mercury(자체 실측): offset 4px, thickness `from-font` 5회·1px 3회, 밑줄 색은 테두리 토큰(`--border-default/emphasized/subdued`) — [mercury.com](https://mercury.com/)
- Stripe offset 2px, 색 inherit / FT 밑줄 두께 2px, 색 토큰 `--o3-color-use-case-link-underline`(자체 실측) — [stripe.com](https://stripe.com/), [ft.com](https://www.ft.com/)
- 스테이징: offset 2–3px, 가림창 '홈으로' 밑줄 색 `--line`(자체 실측).
- 제목 줄바꿈: Stripe `text-wrap:pretty` 24회·`balance` 6회, Vercel `balance` 20회·`pretty` 16회, Linear·Mercury 도 사용(자체 실측) — 고급 사이트의 공통 디테일.
- 숫자: Linear `lining-nums tabular-nums slashed-zero`, Stripe `"tnum"`, 토스 `tabular-nums`(자체 실측).

### Inferences
- KOSAI 본문(17px): 두께 **1px**, offset **0.2em(≈3.4px)**, 밑줄 색 ink **35%**(`#a9a8a7`), hover 에서 ink 100%. 한글은 받침이 기준선 가까이 내려와 offset 2px 이하면 밑줄이 받침에 닿아 보인다(추정). `text-decoration-skip-ink:auto` 는 한글에 영향이 거의 없다.
- 링크 색은 바꾸지 않는다(파랑 없음) — 밑줄이 링크의 유일하고 충분한 신호(WCAG 1.4.1 비색 신호). 밑줄 색 대비는 규범 요건이 아니다.
- 외부 링크: 글자 뒤 `↗` 0.8em · `margin-left:.125em`(Vercel) + 새 창이면 `<span class="sr-only">(새 창)</span>`.
- 눈썹(eyebrow): 한글은 대소문자가 없어 '대문자+자간' 기법이 안 먹는다. 한글 눈썹은 **13px/600 · 자간 0 · ink 55%**, 라틴 대문자 눈썹을 쓸 때만 12px · 자간 0.06–0.08em. 헌장이 지운 영어 킥커를 되살리지 않는다(추론).
- 절 번호: '01' 식 두 자리 tabular 13px/600 ink 30%(현재 `.sec-h .num`) — 대비 1.96:1 이라 장식으로만 읽힌다(계산). 번호가 정보라면(목차와 대응) ink 55% 이상.
- 기준 시각: `2026.09.26 15:30 기준` 13px tabular ink 55–62%, 숫자와 '기준' 사이 공백 하나, 초 단위·요일은 뺀다. 장중이면 '15:30 기준 · 20분 지연' 처럼 지연을 같은 줄에(추론 — 출처 확보 못 함).

### Gaps
- FT·Bloomberg 의 '기준 시각' 표기 규격은 JS 렌더·봇 차단으로 측정하지 못했다.
- 한글 받침과 밑줄 offset 의 최적값은 실기기 캡처로 확인해야 한다.

## 5. 라벨 · 배지 · 칩 — 편집 체계에서 언제 허용되나

### Takeaway
이번에 본 고급 사이트들은 **채운 배지를 거의 쓰지 않는다** — 상태는 작은 글자(+필요하면 점), 분류는 글자 목록. 칩은 '필터를 켜고 끄는 컨트롤'일 때만 정당하다.

### Cited Findings
- NN/g: 이름 없는 아이콘·모호한 요소에만 보조 설명을 붙이고 핵심 정보는 화면에 그대로 두라 — [NN/g Tooltip Guidelines](https://www.nngroup.com/articles/tooltip-guidelines/)
- 색만으로 상태를 전하지 말라(오류도 굵기·아이콘 등 중복 표시) — [NN/g Error Message Guidelines](https://www.nngroup.com/articles/error-message-guidelines/)
- 토스 기업 사이트의 포커스·강조는 파랑 `#3182f6` 한 색, 회색 단계 `#4e5968`·`#333d4b`·`#8b95a1`·`#f2f4f6`(자체 실측, toss.im) — 색 수를 줄인 체계.

### Inferences
- KOSAI 허용: ① **글자 라벨**(13px/500, 대문자 없음, 색은 뜻 있을 때만: 상승·하락·오류) ② **점 + 글자**(6px 원, 상태 셋 이하: '장중'·'마감'·'지연') ③ **선택 칩**은 업종·필터 토글에만 — 켜진 칩은 ink 배경·반전 글자(헌장 `--fg-1` 표의 '선택 칩 배경'), 꺼진 칩은 1px 테두리 없이 글자만.
- 금지: 'NEW'·'AI'·'HOT' 채운 배지, 그라데이션 배지, 아이콘+배지 조합 — "AI 느낌"의 대표 지문(추론, 헌장 금지 목록과 같음).
- 유료화 뒤 '구독' 표시는 배지가 아니라 **자물쇠 선 아이콘 12–14px + '구독' 글자**(추론).

### Gaps
- 없음(편집 체계의 배지 사용 빈도는 측정하지 않았다).

## 6. 피드백 — 툴팁, 토스트, 확인 창, 빈 상태, 로딩

### Takeaway
고급 제품의 피드백은 **덜 띄우고 제자리에서** 준다. 툴팁은 아이콘 단추 이름에만(지연 ~0.7초, 연속 이동 시 즉시), 토스트는 가능하면 피하고(GitHub Primer 는 비권장), 확인 창은 되돌릴 수 없는 일에만 **동사 단추**로, 빈 상태는 글자로 상태·배움·길 하나, 로딩은 1초 안이면 아무것도 보이지 않는다.

### Cited Findings
**툴팁**
- Radix 기본값: `delayDuration` **700ms**, `skipDelayDuration` **300ms**(한 툴팁을 본 뒤 300ms 안에 옆으로 가면 즉시), 화살표 10×5px, `sideOffset` 0. Tab 포커스는 지연 없이 열림, Esc 로 닫힘 — [Radix Tooltip](https://www.radix-ui.com/primitives/docs/components/tooltip)
- NN/g: 과업에 필수인 정보는 툴팁에 두지 말 것, 짧게, **hover 와 키보드 포커스 둘 다**, 요소가 몰려 있으면 화살표, 사이트 전체 일관 — [NN/g Tooltip Guidelines](https://www.nngroup.com/articles/tooltip-guidelines/)
- Primer: IconButton 이름 표시에만, 비대화형 요소(`div`·`span`·`p`)에 금지, 짧게, 터치 기기에서는 문제라 모달·펼침·상시 표시로 대체 — [Primer Tooltip](https://primer.style/product/components/tooltip/guidelines/)

**토스트**
- Sonner 기본값: 위치 bottom-right, 4000ms, 동시 3개, 간격 14px, 가장자리 32px(화면 폭 600px 미만은 16px), 닫기 단추 없음 — [Sonner Toaster](https://sonner.emilkowal.ski/toaster)
- GitHub Primer: 토스트는 **비권장**. WCAG 2.2.1(시간 연장 수단 필요), 4.1.3(보조기기에 방해 없이 알림), 2.1.1(키보드 조작), DOM 위치가 트리거와 떨어짐, 1.4.4·1.4.10·2.4.3 문제. 대안: 결과가 자명한 단순 동작은 **추가 피드백 없음**, 복잡한 동작은 자동으로 사라지지 않는 배너나 제자리 펼침, 오류는 배너/다이얼로그 — [Primer Accessible notifications](https://primer.style/accessibility/toasts/)

**확인 창**
- NN/g: 되돌릴 수 없는 심각한 결과에만, 남발 금지("늑대가 왔다"), '정말요?' 대신 무엇이 일어나는지 구체적으로, Yes/No 대신 **"파일 삭제"/"파일 유지"** 같은 동작 이름, 위험한 선택에 기본값 두지 말 것, **실행 취소(undo)를 1차 수단**으로 — [NN/g Confirmation Dialogs](https://www.nngroup.com/articles/confirmation-dialog/) (2018, 2026-08 재검토)

- NN/g 세 원칙: ① 시스템 상태를 알림('선택한 기간에 표시할 기록이 없습니다' — 로딩 중인데 '없음'이라 하면 신뢰를 잃음) ② 배움의 자리로('즐겨찾기를 누르면 여기 모입니다') ③ 핵심 과업으로 가는 **직접 경로**(링크·단추). 완전히 빈 화면 금지 — [NN/g Empty States](https://www.nngroup.com/articles/empty-state-interface-design/)

**로딩**
- NN/g: **1초 미만**은 스켈레톤·스피너 불필요, **2–10초** 한 모듈은 스피너 · 전체 페이지는 스켈레톤, **10초 초과**는 진행 막대 강력 권장. 머리·바닥만 그린 '틀 스켈레톤'은 쓰지 말 것. 반짝임·맥동 애니메이션은 산만·접근성 문제 소지 — [NN/g Skeleton Screens 101](https://www.nngroup.com/articles/skeleton-screens/) (2023-06, 2026-09 재검토)

### Inferences
- 툴팁: 700ms 는 편집 사이트에 약간 길다 — **500ms**, skip 300ms, 화살표 없음(아이콘 단추가 몰려 있는 헤더도 아래쪽 6px 띄움이면 소속이 분명), 배경 ink `#141414` · 글자 `#f9f8f6` 12–13px/500 · 모서리 6px · 좌우 8px · 높이 26–28px, 터치(`hover:none`)에서는 그리지 않는다.
- 토스트: KOSAI 의 대부분 동작(관심종목 담기·테마 전환·필터)은 결과가 화면에서 자명하다 → **토스트 없음**(☆ → ★, `aria-pressed`). 토스트가 정당한 곳은 **관심종목 빼기 + '되돌리기'**(NN/g: 확인 창보다 undo), 네트워크 오류 정도. 쓸 때: 하단 가운데(모바일 16px) / 하단 오른쪽(데스크톱 32px), 4초, hover·포커스 중 정지, 동시 1개, `role="status"`. 헌장 4.11 의 '4초·200ms 페이드' 와 같다.
- 확인 창: 계정 삭제·구독 해지만. 단추 '계정 삭제' / '취소'(취소가 기본 포커스), 본문은 결과 한 문장('관심종목 12개와 설정이 지워지고 되돌릴 수 없습니다').
- 빈 상태: **일러스트 없이 글자만** — 제목 17–20px/600(상태), 설명 15px ink 62%(배움), 밑줄 링크 하나(길). 아이콘은 헌장 4.11 의 40px 선 아이콘을 쓰더라도 1.75px 한 색.

### Inferences
- 헤더: 바탕 `rgba(249,248,246,.85)` + `blur(12–16px)` + **스크롤한 뒤에만** 1px 선 ink 8%(Linear 식), 다크는 반전. iOS 가장자리 띠(`#kosEdgeTop/Bot`)와 겹치므로 불투명도 ≥.8 유지.

- 맨 위로: 종목 리포트(13개 절, 모바일에서 화면 4개를 훌쩍 넘음)에만. 오른쪽 아래 글자 단추 '맨 위로 ↑' 13px, 위로 스크롤할 때만 보이기. 데스크톱은 목차 레일이 있으니 생략 가능.

### 우선순위 권고 (효과 ÷ 수고 순)

1. **아이콘 렌더 굵기 통일(1.5px)** — 지금 단추 안 16px·stroke 2(→1.33px), '더보기' 14px·2(→1.17px), 가림창 자물쇠 30px·1.4(→1.75px)가 섞여 있다(계산). `comp_common.CSS` 에서 모든 인라인 SVG 에 `vector-effect:non-scaling-stroke; stroke-width:1.5` 를 주고 예외는 40px 빈 상태 하나. 검사는 헌장 571행의 'stroke-width 화이트리스트'를 렌더 굵기 기준으로 바꾸면 된다.
2. **검색·폼의 IME 가드** — Enter 처리 전부에 `e.isComposing` 확인. 한글 사이트에서 조합 중 Enter 오동작은 기능 결함이면서 가장 흔한 '미완성' 신호다. 한 줄 수정.
3. **단추 두 칸(40 / 48)으로 정리** — 모바일 전폭 44 를 48 로 합치고, 48 단추 글자 16px/600, hover 를 `opacity:.9` 에서 배경 `#2b2b2b` 로. 로딩 상태(폭 고정·`aria-busy`)를 공용 클래스로 하나 만든다. 헌장의 '알약형 CTA 금지' 문장은 현재 방향에 맞게 고친다.
4. **링크 토큰 하나** — 두께 1px · offset 0.2em · 밑줄 색 ink 35% → hover 100%. 지금 offset 2px·3px 와 밑줄 색 `--line` 이 페이지마다 다른 것을 한 규칙으로. 외부 링크 `↗` 규칙 추가.
5. **폼 규격(48px 칸 · 위 라벨 · blur 검사 · 즉시 해제 · 테두리 ink 48%)** — 로그인·가입·결제(checkout) 모두. 테두리 40% 이하면 WCAG 1.4.11 미달(계산 2.56:1).
6. **소셜 로그인 셋 동일 규격 + 모서리 12px** — 카카오 규정(12px·`#FEE500`·검정 85%·'카카오 로그인')을 지키고, 구글·네이버도 같은 높이·폭·모양으로. 네이버 원문 규격은 러너에서 받아 확인(이 환경은 차단).
7. **토스트 줄이기** — 결과가 보이는 동작은 토스트를 없애고, 관심종목 빼기만 '되돌리기' 토스트. 확인 창은 계정 삭제·구독 해지에만, 동사 단추로.
8. **빈 상태·로딩 규칙** — 빈 상태는 글자 세 줄(상태·배움·링크), 1초 미만 로딩은 아무것도 그리지 않고 자리만 잡아 흔들림 방지.
9. **파비콘 세트 점검** — Evil Martians 7파일(헌장 4.12 와 같음)이 실제로 있는지 `check_seo.py` 에 파일 존재 검사로(헌장 628행 계획). SVG 안 다크 `@media` 필수 — 다크 탭에서 사라지는 문제 방지.
10. **헤더 스크롤 선** — 스크롤 0 에서는 선 없음, 내려가면 1px ink 8% + bg 85% 블러. iOS 가장자리 띠(`#kosEdgeTop`)와 같이 실기기 확인.
11. **툴팁은 아이콘 단추에만** — 500ms 지연, 화살표 없음, 터치 기기에서 안 그림. 지금 헤더의 테마·검색·☆ 단추가 대상.
12. **OG 템플릿** — 1200×630 한 장 템플릿을 먼저, 종목별 동적 OG 는 저장소 용량(2,682장)을 계산한 뒤 업종·상위 종목부터.
