## 1. 차트 공예 — 최상위 편집 차트의 정확한 사양

### Takeaway
최상위 편집 차트의 공통 문법은 **회색 맥락 + 강조 하나, 범례 대신 직접 라벨, 옅은 가로 격자만, 0선만 진하게, 제목은 주장·부제는 단위** 다. 수치를 가장 구체적으로 공개한 것은 Economist 2017 가이드다 — 웹 1단 290px·2단 595px, 제목 9.5pt(웹 ≈17px)·축 7pt(≈12.5px)·출처 6.5pt 75% 검정, 격자 `#B7C6CF`, 검정은 0선에만.

### Cited Findings
- **Economist 크기**: 인쇄 1단 160pt = 웹 290px, 2단 332pt = 웹 595px. "웹 차트는 인쇄 폭으로 만들어 179.22% 로 내보낸다" — [Economist CHART style guide v1.2, 2017-05-04 (PDF 사본)](https://sa.ipaa.org.au/wp-content/uploads/2026/02/Economist-CHARTstyleguide_20170505.pdf) (원래 주소 design-system.economist.com/documents/… 는 이제 첫 화면으로 넘어간다)
- **Economist 글자(표준 인쇄 차트)**: 제목 Econ Sans bold 9.5/11pt · 부제 Econ Sans Cnd regular 8/9.5 · 라벨 cnd light 7.5/9 · 축 라벨 cnd reg 7/7.5 · 출처 cnd light 6.5pt **75% 검정**. "가능하면 단위와 날짜는 둘째 줄에 더 작은 글자로", "부제는 차트를 요약하고 구체 단위는 축 라벨에 남겨라" — 같은 PDF 6·18쪽
  - 실측(계산): ×1.7922 하면 웹에서 제목 17.0px · 부제 14.3px · 라벨 13.4px · 축 12.5px · 출처 11.7px.
- **Economist 선**: 치수 도해에 1pt · 0.5pt · 0.4pt 세 굵기가 표기(웹 환산 1.8 · 0.9 · 0.7px). "x·y 눈금은 같은 굵기·색", "**검정은 0 기준선에만**", "x축 기준선은 마지막 눈금에서 끝낸다", 끊긴 눈금 기호 "검정 0.4 stroke, 폭 6pt, 기준선과 첫 눈금 사이 가운데" — 같은 PDF 6·18·25쪽. (세 굵기가 각각 어느 요소인지는 텍스트 추출로 확정 못 함 → Gaps)
- **Economist 산점도**: 일반 점 4px·불투명 50%, 강조 점 4px·100%, 추세선 1px 점선(3px, 1px) — 같은 PDF 18쪽
- **Economist 웹 팔레트**: Econ red `#E3120B` · 검정 `#0C0C0C` · 계열 `#006BA2 #3EBCD2 #379A8B #EBB434 #B4BA39 #9A607F #D1B07C #DB444B`, 격자·회색 상자·회색 글자 줄에 `#B7C6CF #E9EDF0 #758D99 #3F5661` — 같은 PDF 12쪽. 격자 `#B7C6CF` 1px 는 [AECharts (2차)](https://aecharts.com/blog/posts/how-to-create-charts-like-the-economist/) 도 같은 값. 실측: `#B7C6CF` 는 흰 바탕 대비 1.75:1.
- **Economist 규칙**: "양/음 값을 색으로 가르는 것은 수출·수입처럼 **의미 있는 차이가 있을 때만**" · "막대·기둥 차트는 눈금을 끊지 마라(온도계형을 써라)" · "이중 눈금은 상관을 보이기엔 경제적이지만 혼란·오도할 수 있다 — 0선 위아래를 그리면 0선을 맞춰라, 규칙을 못 지키면 **패널로 나누거나 지수화하라**" · "예측·추정 같은 2차 정보는 중립 스타일" · "리더 박스 차트는 격자·눈금 라벨을 최소로, 모든 점의 값보다 **분명한 메시지 하나**" · 패널 사이 24pt · 여백 없음 · 흰 바탕 — 같은 PDF 3·8·13·21·25쪽
- Economist 는 y축을 **오른쪽**에 둔다 — 최신 값이 그 숫자 옆에 오게. 모든 차트 위에 1px 빨간 선과 왼쪽 끝 40×10px 빨간 사각형 — [AECharts (2차)](https://aecharts.com/blog/posts/how-to-create-charts-like-the-economist/)
- **FT**: 그래픽은 "제목, 범례(또는 요소에 직접 라벨), 데이터 출처, 변수→시각 차원의 대응" 을 갖춘다; 목표는 "데이터를 왜곡하지 않고 눈이 비교하게" — [FT graphics-style-guide](https://github.com/Financial-Times/graphics-style-guide/blob/master/index.md). FT 차트는 흰 상자 없이 연어색 바탕에 바로 앉고, 격자는 "거의 안 보이게", 제목·주석은 본문과 같은 서체 — [Curio, FT 디자인 해설 (2차)](https://designbycurio.com/learn/financial-times-pink-paper)
- **FT Visual Vocabulary** 9갈래: 편차(Deviation: 발산 막대·흑자/적자 채운 선) · 상관 · 순위(정렬 막대·점 띠·롤리팝, "관심 점을 강조하길 두려워 마라") · 분포 · 시간 변화("기간 선택이 중요") · 부분-전체 · 크기(Magnitude: "막대·기둥은 0에서 시작해야") · 공간 · 흐름 — [FT chart-doctor Visual Vocabulary](https://github.com/Financial-Times/chart-doctor/blob/main/visual-vocabulary/README.md)
- **Datawrapper 선 차트**: 색·굵기·점선으로 중요한 값을 세우고 비교 값은 회색; 범례 대신 선 끝 직접 라벨(모바일에서는 색 키로 바뀜); 값이 0 가까우면 y축을 0까지; 곡선 보간 금지; 간격이 불규칙할 때만 점 표식 — [Datawrapper, line charts](https://www.datawrapper.de/blog/line-charts)
- **Datawrapper 글자**: 웹에서 읽히는 글자는 ">12px"; 위계는 뚜렷이 다른 **두 단계**; 주 정보는 "(거의) 검정", 출처·설명은 "작고 가늘고 회색"; "축 라벨은 기둥 차트 외에는 절대 회전하지 않는다"; 가운데 정렬보다 왼·오른쪽 정렬; `0.[0]%` 처럼 필요할 때만 소수 — [Datawrapper, text in data vis](https://www.datawrapper.de/blog/text-in-data-visualizations)
- **Datawrapper 회색**: "회색은 데이터 시각화에서 가장 중요한 색"; "격자는 축 라벨보다 옅게, 제목·설명은 더 짙게"; Economist 는 따뜻한 회색 RGB(135,135,113)·(207,209,195) — [Datawrapper, colors for style guides](https://www.datawrapper.de/blog/colors-for-data-vis-style-guides/)
- **막대 간격**: Datawrapper 기본 ≈막대 폭의 20%, Flourish 10%, Venngage ≈50%; "대개 20–40%", 한 발표 안에서 일정하게. 너무 붙으면 한 덩어리(히스토그램), 너무 벌면 무리로 안 보인다 — [AddTwo, Rule 20 (2차)](https://www.addtwodigital.com/add-two-blog/2021/8/2/rule-20-keep-a-sensible-gap-between-the-bars)
- **Tufte 스파크라인**: 데이터-잉크 비 1.0(테·눈금 없음), 단어 크기·"타이포그래피 해상도"; 세로는 단어 제약 안에서 최대로 쓰고 가로로 늘려 평균 기울기 45°(banking); 예시 비율 **금융 5:1**·야구 시즌 20:1; 정상 범위는 회색 띠; 오른쪽 끝 점을 옆 숫자에 색 강조로 잇는다(끝점 빨강, 최고·최저 파랑) — [Tufte, Sparkline theory and practice](https://www.edwardtufte.com/notebook/sparkline-theory-and-practice-edward-tufte/)

- **다크 모드**: Datawrapper 자동 다크는 "각 요소의 바탕 대비를 라이트와 똑같이" 유지 — 흰 바탕의 아주 어두운 색은 검은 바탕에서 아주 밝게. 테마별로 다크 짝 색을 따로 정할 수도 있다 — [Datawrapper, dark mode](https://www.datawrapper.de/blog/dark-mode-for-embedded-visualizations)

### Inferences
- '고급'의 핵심은 색이 아니라 **위계의 절제**다: 데이터 1색(먹) + 맥락 1색(옅은 먹) + 의미색(등락) 뿐. KOSAI 헌장의 '차트 채도 0' 과 같은 방향이다.
- Tufte 의 빨강/파랑 끝점 관례는 한국에서 그대로 쓰면 안 된다 — 빨강·파랑이 이미 상승·하락이다. 끝점 강조색 = **그 행의 등락색**으로 바꾸면 Tufte 의 '끝점을 옆 숫자에 잇는다' 가 한국 관례와 맞물린다(추정).
- 편집 차트(1~2px)와 트레이딩 차트(3px)의 선 굵기 차이는 목적 차이다. 리포트는 '읽는 차트' 이므로 1.5~2px 가 맞다(추정, Economist 웹 환산 1.8px 와 일치).

### Gaps
- Economist PDF 의 1pt·0.5pt·0.4pt 가 각각 0선·격자·눈금인지(가장 그럴듯한 배정) 텍스트만으로는 확정 못 했다. 데이터 선 굵기 수치도 PDF 텍스트에 없다.
- FT 의 수치 사양(`g-chartframe` 프레임·글자 크기)은 저장소 접근이 막혀 못 열었다. Bloomberg·Reuters 그래픽 스타일 가이드는 공개본을 찾지 못했다.

## 2. 금융 표기 관례 — 등락색·부호·화살표·원/억/조·소수·음수

### Takeaway
한국은 상승 빨강·하락 파랑이고, **KOSAI 의 빨강 `#c8102e`/파랑 `#1e5fbf` 쌍은 적록 색각이상에서도 잘 갈린다(ΔE 75~102, 미국식 초록/빨강은 20~22)** — 그러나 두 색의 밝기가 같아(대비 1.04:1) 흑백·저시력에서는 한 색이 된다. 그래서 부호(+/−)는 필수, 화살표는 머리 숫자에만. 증권사 1면은 **표 위에 단위 한 줄**('(십억원, 원, %, 배)')을 두고 셀은 숫자만 쓴다.

### Inferences
- 한국 증권사 1면은 음수 표기가 괄호(유안타)·하이픈(대신·한화)으로 갈린다 — 업계 표준이 없다. 소매 독자용 웹에는 괄호보다 **U+2212 + 색** 이 낫다(괄호는 회계 독자용이고 '(1.8)' 이 주석 번호처럼 읽힐 수 있음 — 추정).
- '표 위 단위 한 줄 + 셀은 숫자만' 은 증권사 4곳 모두 같다. 한 열 안에서 '1.5조'·'3,120억' 이 섞이면 Butterick 의 '같은 뜻의 자리 정렬' 이 깨진다. 헌장 4.5 가 셀 단위를 뼈대로 묶어 두었으니 **대표 결정 항목**으로 올릴 값이 있다.
- `Intl` 을 그대로 쓰면 하이픈이 나오므로 포매터 끝에서 `-`→`−` 치환이 필요하다.

### Gaps
- 토스증권·네이버페이 증권·카카오페이증권·업비트의 공식 표기 규칙 문서는 찾지 못했다. 네이버 종목 페이지는 내려받았지만 Next.js SPA 라 HTML 에 수치·클래스가 없다. Koyfin·Yahoo·Robinhood 의 음수·소수 규칙은 확인 못 함.
- '원' 앞 띄어쓰기(제43항 '다만' 조항) 원문은 이번에 열지 않았다.

## 3. 표 — 행 높이·선·정렬·머리·고정 열·휴대폰 밀도

### Takeaway
금융 표의 최상단 문법은 **열린 표(외곽·세로선 없음) + 헤어라인 행 + 오른쪽 정렬 tabular 숫자 + 색은 변화율 열에만** 이다. 휴대폰에서는 비교가 목적이면 **첫 열 고정 + 잘린 열로 '더 있음' 을 보이는 가로 스크롤**, 비교가 아니면 열 선택. 줄무늬는 복잡한 넓은 표에서만 이득이 입증됐다.

### Cited Findings
- NN/g: 확대 없이 읽혀야 한다; 한 화면 넘는 표는 **머리 고정**; 가로 스크롤 시 **왼쪽 첫 열 고정**; "가로 접힘 너머에 데이터가 더 있다는 것이 분명해야" — **잘린 요소·화살표**가 잘 통하고 점(dot)은 자주 놓친다; 숫자 위주 표는 좁은 열로 11열까지 보인 예(NRL); 대안은 보기 전에 데이터 고르기·열/행 토글·아코디언; 가로 회전 강요 금지 — [NN/g, Mobile Tables](https://www.nngroup.com/articles/mobile-tables/)
- 줄무늬(Enders): 첫 실험은 속도 향상 없음·정확도 약간·'읽기 쉽다' 는 느낌; 후속 실험은 **복잡한 표에서** 효율·정확도 향상의 더 강한 근거 — [A List Apart, Zebra Striping: Does it Really Help?](https://alistapart.com/article/zebrastripingdoesithelp/) · [More Data for the Case](https://alistapart.com/article/zebrastripingmoredataforthecase/)
- Butterick: 불필요한 색·테두리 제거, 행 간격 일정, 숫자 열 오른쪽 정렬, 머리는 숫자 정렬을 따른다 — [Grids of numbers](https://practicaltypography.com/grids-of-numbers.html)
- Datawrapper: 격자는 라벨보다 옅은 회색 — 표의 행 선도 같은 원리 — [Datawrapper, colors](https://www.datawrapper.de/blog/colors-for-data-vis-style-guides/)
- 증권사 재무표: 행 = 지표(매출액·영업이익·지배순이익·EPS·PER·PBR·ROE…), 열 = 연도(A/F 꼬리표), **표 위 단위, 표 아래 '주:'·'자료:'** 한 줄씩 — 유안타·대신·한화 1면(위 2장 링크)
- 실측(저장소): 헌장 4.5 는 이미 td 15px/24 · th 13px 500 · 행 44px · 셀 패딩 12/16 · 열 간격 ≥16 · 열린 표 · sticky 첫 열 · 카드 스택 금지 · caption/scope 를 정했다(`docs/design/KOSAI-design-charter.md` 4.5).

### Inferences
- 업종 순위 표(휴대폰 358px)는 '종목명 | 등락률 | 시가총액' 3열이 한 화면 기본, 나머지(PER·PBR·배당·스파크라인)는 가로 스크롤로 — 첫 열 고정 + 오른쪽 끝 열이 반쯤 잘려 보이게 폭을 잡으면 NN/g 의 '잘린 요소' 신호가 공짜로 생긴다(추정).
- 줄무늬는 KOSAI 표 대부분(5~8행 재무표)에 필요 없다. 20행 넘는 업종 순위·전 종목 목록에서만 `--bg-3` 한 단계(추정).
- 색은 변화율(등락·YoY)에만, 수준값 음수(적자)는 먹색 + U+2212 — 헌장 4.5 의 규칙은 Economist 의 '의미 있을 때만 양/음을 색으로' 와 같은 논리다.

### Gaps
- 행 높이의 실험적 최적값(예: 36 vs 44 vs 52px) 연구는 찾지 못했다. Material 류 스펙 문서는 JS 렌더라 원문을 못 열었다.

## 4. 리서치 리포트를 웹으로 — 증권사·컨설팅의 배치

### Takeaway
한국 증권사 1면은 네 덩어리로 거의 같다: **① 한 문장 주장 제목 ② 판단 상자(의견·목표가·현재가(기준일)·상승여력) ③ 주가 데이터 띠(시총·52주 고저·거래대금·외인지분·주요주주·1/3/6/12개월 수익률) ④ 연도별 재무·밸류에이션 표(단위·자료 줄)**, 본문은 **굵은 한 줄 소제목 + 문단** 반복. KOSAI 는 ①③④와 '굵은 소제목' 을 빌리고, ② 는 목표가·의견 없이 '판단 요약' 으로만 옮겨야 한다.

## 5. 작은 배수와 비교 도표 — 4년 실적 미니 막대·이중축·PER 점 도표·강세/약세 균형

### Takeaway
매출·영업이익·순이익을 **한 축에 묶지 말고**, 같은 x(연도)·각자 0 기준 y 의 **세 칸 작은 배수**로 그린다. 마진 선을 막대 위에 따로 스케일해 겹치는 것은 숨은 이중축이다. 적자는 0선 **아래로**, 채움 없는 윤곽선으로.

### Cited Findings
- Economist: 이중 눈금 → "패널로 나누거나 지수화"; 0선 위아래 → "0선을 맞춰라"; 막대 눈금 끊기 금지 — [Economist PDF 21·25쪽](https://sa.ipaa.org.au/wp-content/uploads/2026/02/Economist-CHARTstyleguide_20170505.pdf)
- FT: 크기 비교 막대는 0에서 시작; 양·음 편차는 발산 막대/흑자·적자 채운 선; 순위·위치는 **점 띠(dot strip)·롤리팝** — [FT Visual Vocabulary](https://github.com/Financial-Times/chart-doctor/blob/main/visual-vocabulary/README.md)
- Datawrapper 는 작은 배수 선 차트를 정식 차트형으로 제공한다 — [Datawrapper, small multiple line charts](https://www.datawrapper.de/blog/small-multiple-line-charts)
- 실측(저장소 · 실사이트 `stock.html` `kBarChart`): 매출·영업이익을 한 y 스케일에 나란히 그리고, 영업이익률 선을 **자기 스케일**로 같은 판 위에 얹는다(숨은 이중축). 적자 막대는 `--c-loss` 빨강 채움.
- 실측(저장소 · 스테이징 `scripts/stock_page.py` `bar_chart`): 막대 높이가 `plot_h * max(val, 0) / mx` 이고 최소 2px — **음수(적자)가 0선 위 2px 막대로 그려지고** 라벨만 음수를 말한다. 영업이익 막대 `--ink-30` 은 바탕 대비 **1.96:1**(WCAG 1.4.11 의 3:1 미달). 매출 조 단위 옆에서 저마진 기업의 영업이익 막대는 몇 px 로 눌린다(같은 축이라서).

### Inferences
- **4년 미니 막대 사양(추정)**: 칸 폭 = 판 폭/3 − 간격, 막대 4개, 막대 간격 = 막대 폭의 30~40%(AddTwo 20–40% 의 위쪽 — 막대가 4개뿐이라 덩어리처럼 안 보이게), 0선 1px 먹, 격자 없음, **값 라벨을 막대 위에 직접**(y축 라벨 불필요), 최신 해만 먹 100%, 앞 3년은 `--ink-55`(4.01:1 로 3:1 통과), 적자는 0선 아래 1px 먹 윤곽선 + '−300억'. 칸 제목 = '영업이익' + 오른쪽에 최신 값·YoY(등락색).
- **PER 대 업종**: 가로 한 줄 점 도표 — 업종 P25~P75 회색 띠(`--bg-3`), 업종 중앙값 세로 눈금 1px, 종목 점 8px 먹, 라벨 '12.4배 · 업종 중앙 9.8배'. 적자로 PER 이 없으면 점을 그리지 않고 '적자 — PER 산출 안 됨'(FT 편차·순위 문법의 응용, 데이터 가용성 확인 필요).
- **강세/약세 균형**: 게이지·저울·온도계 없이 두 열 같은 폭, 머리에 '강세 요인 4 · 약세 요인 3' 개수만. 빨강/파랑을 쓰지 않는다 — 한국 독자에게 빨강=상승이므로 '강세=빨강' 은 가격 신호로 오독된다. 구분은 글자('강세'/'약세')와 위치로.

### Gaps
- 강세/약세 균형 표현의 사용자 연구는 찾지 못했다(위는 원칙에서 끌어낸 추정).

## 6. 모바일 차트 — 358px 폭, 라벨 충돌, 숫자로 바꿀 때

### Takeaway
휴대폰에서 차트가 망가지는 첫 원인은 **viewBox 축소로 글자가 같이 줄어드는 것**이다. KOSAI 스테이징 종목 차트는 358px 폭에서 13px 라벨이 **8.9px** 가 된다. 폭별로 그리거나 라벨을 HTML 로 빼고, 눈금은 손으로 고른 3~4개, 회전 라벨 금지, 범례는 직접 라벨로.

### Cited Findings
- Economist 웹 1단 차트는 **290px** 폭으로 완결된다(제목·부제·축·출처 포함) — 휴대폰 한 칸 폭이 차트의 정상 크기라는 근거 — [Economist PDF 4쪽](https://sa.ipaa.org.au/wp-content/uploads/2026/02/Economist-CHARTstyleguide_20170505.pdf)
- Datawrapper: 눈금은 몇 개만 골라 반올림; 회전 라벨은 읽기 어렵고 자리를 더 먹어 피한다; 선 끝 라벨은 모바일에서 색 키로 바뀐다; 날짜 눈금은 두 층(연·월)을 두 줄로, 넘치면 숨긴다 — [Datawrapper 검색 요약: mobile·axis ticks](https://www.datawrapper.de/blog/new-axis-ticks) · [line charts](https://www.datawrapper.de/blog/line-charts)
- NN/g: 확대 없이 읽혀야 한다 — [Mobile Tables](https://www.nngroup.com/articles/mobile-tables/)
- 실측(계산·저장소): 스테이징 `bar_chart` viewBox 520 × `.ch{width:100%}` · `@media(max-width:820px){.tiles{grid-template-columns:1fr}}` → 358px 에서 13px × 358/520 = **8.95px**. 실사이트 `stock.html` 은 같은 문제(10.5px × 358/620 ≈ 6.1px)를 `min-width:580px` + 가로 스크롤로 막아 두었다(주석: "숫자 라벨이 ~6px로 작아짐").
- Tufte: 금융 스파크라인 5:1, 단어 높이 — [Sparkline theory](https://www.edwardtufte.com/notebook/sparkline-theory-and-practice-edward-tufte/)

### Inferences
- 차트를 가로 스크롤시키는 것(실사이트 방식)은 '한눈에 추세' 라는 차트의 목적을 깬다. 서버에서 **폭 두 벌**(데스크톱 520 · 휴대폰 358 viewBox)을 그려 `media` 로 바꾸거나, 값·연도 라벨을 SVG 밖 HTML 격자로 두면 글자가 1:1 이 된다(추정).
- **숫자로 바꿀 때**(추정): 점이 3개 이하, 메시지가 숫자 하나('영업이익 3년 연속 증가'), 또는 358px 에서 라벨이 막대 폭보다 넓어 겹칠 때 — 차트 대신 '2022 → 2025: 1.2조 → 3.4조' 한 줄 + 작은 스파크라인.
- 358px 에 4년 막대 3칸(작은 배수)은 한 줄에 안 들어간다 → 휴대폰은 **세로로 3칸 쌓기**(칸 높이 96~112px) 또는 가로 스와이프 없이 2+1(추정).

### Gaps
- 휴대폰 차트의 라벨 최소 크기에 대한 실험 연구는 찾지 못했다(Datawrapper 의 '>12px' 가 최선의 근거).

## 7. 접근성 — 색각이상 안전 등락, 라벨, 차트 ARIA, 표 의미론

### Takeaway
차트는 **짧은 대체 텍스트(무엇·결론) + 긴 설명(표)** 두 겹, 표시는 **색 + 부호 + 글자** 세 겹, 막대·선은 바탕 대비 **3:1**, 라벨은 4.5:1 의 살아 있는 텍스트. KOSAI 등락색은 색각이상엔 안전하지만 밝기가 같아 부호 없이는 실패한다.

### Cited Findings
- W3C WAI: 복잡한 이미지는 짧은 대체 텍스트(차트 종류·핵심 내용) + 긴 설명; 긴 설명은 인접 텍스트 링크 · `figure/figcaption`(표·제목을 담을 수 있음) · `aria-describedby`(단, "참조된 요소는 하나의 이어진 문단으로 읽힌다" — 표 같은 구조는 못 담음) — [W3C WAI, Complex Images](https://www.w3.org/WAI/tutorials/images/complex/)
- 인라인 SVG 는 `role="img"` + `aria-labelledby`, 장식 SVG 는 `aria-hidden`; 같은 데이터로 만든 **형제 `<table>`** 이 대체의 기둥; 모든 계열에 두 번째 단서(직접 라벨·패턴·모양·점선); 표식 3:1, 라벨 4.5:1, 라벨은 구운 픽셀이 아닌 텍스트 — [accessibility.build (2차)](https://accessibility.build/guides/accessible-charts)
- WCAG 2.x: 색만으로 정보를 전달하지 않는다(1.4.1), 이해에 필요한 그래픽 요소는 인접색 대비 3:1(1.4.11) — [W3C, Understanding 1.4.1](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) · [1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). Datawrapper 는 "공개된 스타일 가이드 대부분이 데이터 요소의 대비 기준을 다 지키지 못한다" 고 적는다 — [Datawrapper, colors](https://www.datawrapper.de/blog/colors-for-data-vis-style-guides/)
- Apple(WWDC22 'Design an effective chart'): 색끼리·차트 나머지와 높은 대비, 색각이상 필터로 확인, 축 범위·격자로 값을 한눈에 — [Apple Developer, WWDC22 110340](https://developer.apple.com/videos/play/wwdc2022/110340/) (HIG 'Charting data' 본문은 JS 렌더라 못 열었다)
- 실측(계산): 먹 `#141414` 을 바탕 `#f9f8f6` 에 얹을 때 3:1 이 되는 최소 불투명도 **0.46**(`#908f8e`); `--ink-30` 1.96 · `--ink-55` 4.01 · `--ink-72` 7.15. 다크(`#ececea` on `#0d0d0e`)는 최소 **0.37**; `--ink-30` 2.41 · `--ink-55` 5.45. 다크 등락 `#f0655f` 6.23 · `#6f9cf5` 7.17.

### Inferences
- 차트마다 `<figure>` 안에 `<svg role="img" aria-labelledby="캡션id 요약id">` + `<figcaption>`(제목 = 주장 한 문장) + 시각적으로 숨긴 요약 한 줄('영업이익 2022년 1.2조 원에서 2025년 3.4조 원으로 증가, 2023년 적자') + 바로 아래 재무표가 긴 설명 구실을 한다 — KOSAI 는 이미 재무표가 차트 옆에 있어 비용이 거의 없다(추정).
- '맥락' 막대·선의 최저 농도는 라이트 `--ink-55`, 다크 `--ink-55`(둘 다 3:1 통과) — `--ink-30` 은 격자·장식에만.

### Gaps
- 한국어 스크린리더(VoiceOver 한국어·센스리더)에서 SVG `role="img"` 읽기 품질을 직접 시험하지 못했다.

### 숫자 표기 규칙

1. **음수** — U+2212 `−`(하이픈 아님). Pretendard 에서 '+' 와 폭이 같다(실측). `Intl` 은 하이픈을 내므로 포매터 끝에서 치환. 괄호 음수는 쓰지 않는다(증권사도 갈림).
2. **부호** — 변화(등락률·YoY·전일比·%p)는 항상 부호: `+2.31%` · `−1.20%` · `0.00%`(부호 없음, `--ink-55`). 수준값(영업이익·순이익)은 음수만 `−`.
3. **화살표** — ▲▼ 는 종목 머리 등락·홈 지수처럼 '가격 한 줄' 에만. 표 셀에는 부호 + 색 두 겹(세 번째는 `sr-only` '상승/하락').
4. **금액 단위** — 문장·KPI: 한국어 만 단위 띄어쓰기 '1,616조 4,960억 원'(제44항), 타일은 반올림 '1,616조 원'. 표: 한 열 한 단위(억 원 정수 + 쉼표)†. 영문: `₩1.6T` / `₩312.0B`.
5. **% 소수** — 등락률 2자리, 마진·ROE·배당수익률·YoY 1자리, 퍼센트끼리의 차는 `%p`(증권사 '%pt'), `0.[0]` 식 끝 0 잘라내기는 쓰지 않는다(열 정렬이 깨짐).
6. **배수** — PER·PBR·EV/EBITDA 1자리 + '배'(영문 `x`). 적자 PER 은 '—' 가 아니라 '적자' 글자.
7. **주당 값** — EPS·BPS·DPS·주가: 원 정수 + 쉼표.
8. **빈값** — em dash `—`(U+2014) + 표 아래 사유(헌장 2.11).
9. **기준 시각** — 모든 숫자 덩어리에 '기준' 하나: '시세 2026-09-25 장마감 · 재무 2025-12-31 연결 · 리포트 2026-09-20'. 증권사처럼 현재가 옆에 '(9/25)'.
10. **단위 글자 농도** — '원·억·조·%·배' 는 값과 같은 크기, `--ink-55`†(Mercury 의 '통화 기호를 옅게' 를 한글로).

### 우선순위 권고

1. **[버그] 스테이징 `bar_chart` 의 음수 클램프 고치기** — `max(val, 0)` 때문에 적자가 0선 위 2px 막대로 그려진다. 0선 아래 윤곽선 막대로. 숫자의 정직함(헌장 원칙 ②) 위반이라 가장 먼저.
2. **[버그] 휴대폰 차트 글자 축소 없애기** — 358px 에서 13px → 8.9px. 폭 두 벌 viewBox(520·358)를 서버에서 그려 `@media` 로 바꾸거나 라벨을 HTML 로. 실사이트식 가로 스크롤 차트는 쓰지 않는다.
3. **실적 차트를 작은 배수 3칸으로** — 매출·영업이익·순이익 각자 0 기준, 같은 연도 축. 저마진 기업의 영업이익이 매출 옆에서 눌리는 문제와 대비 1.96:1 문제가 같이 풀린다. 막대는 `--ink`(최신)·`--ink-55`(이전).
