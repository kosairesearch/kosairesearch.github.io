# 01 색 이론과 팔레트 — 종이 위 리서치 리포트의 색 체계 (라이트 · 다크)

조사 범위: 색공간(OKLCH/OKLab vs HSL) · 따뜻한 무채색 사다리 · 강조색 전략과 실제 면적 · 한국식 등락색(빨강 상승/파랑 하락)의 정확한 값 · WCAG 2.2 vs APCA · 다크 모드 · 색 심리와 유행 · 도구와 토큰 구조.
기준(고정): 바탕 `#f9f8f6` · 먹 `#141414` · 다크 바탕 `#0d0d0e` · Pretendard · 픽셀 90% 이상 무채색 · 그라데이션/카드/알약 없음 · 상승 빨강/하락 파랑. 현재 스테이징 토큰(`scripts/comp_common.py` 실측): 라이트 `--ink-72/55/30 = rgba(20,20,20,.72/.55/.30)` · `--hair .08` · `--line .14` · `--up #c8102e` · `--down #1e5fbf` · `--surface-2 #f1efeb`; 다크 `--ink #ececea` 와 같은 알파 · `--surface #161617` · `--surface-2 #1e1e20` · `--up #f0655f` · `--down #6f9cf5`.

방법과 표기:
- **실측(계산)** = 이 세션에서 계산한 값: WCAG 2.x 대비, **APCA-W3 0.0.98G-4g** 직접 구현 Lc(음수 = 다크 바탕 위 밝은 글자, 절댓값으로 읽는다), OKLab/OKLCH(Ottosson 행렬), 색각이상은 [Machado·Oliveira·Fernandes 2009](https://www.inf.ufrgs.br/~oliveira/pubs_files/CVD_Simulation/CVD_Simulation.html) severity 1.0 행렬(선형 RGB), 색차 ΔE = OKLab 거리×100(구별 한계 ≈2 는 추정).
- **실측(사이트)** = 2026-09-26 이 세션에서 curl 로 받은 CSS 토큰, 그리고 Playwright Chromium 1440px 폭 전체 페이지(최대 7,000px) 스크린샷의 픽셀을 OKLCH 로 바꿔 **C ≥ 0.04 인 픽셀 비율 = "유채색 면적"**, C ≥ 0.10 = "선명한 색 면적". 사진·일러스트가 포함되므로 "강조색 면적의 상한"으로 읽어야 한다. 봇 차단(403)된 FT·Economist·Bloomberg·Aesop·Hermès·NYT·Celine·Bottega·Loro Piana 는 면적에서 뺐다(FT 는 CSS 토큰만).
- **추정** = 출처가 아니라 내 판단. (2차) = 2차 자료.

## 1. 색공간과 무채색 사다리 — OKLCH 로 만들고 hex 로 굳힌다

### Takeaway
팔레트는 **OKLCH 에서 설계**해야 한다. HSL 의 L 은 색상마다 체감 밝기가 달라서 '같은 단계'가 같은 무게로 보이지 않는다. KOSAI 의 따뜻한 사다리는 색상각 85°(바탕 `#f9f8f6` 의 색상각), 채도 C 0.003~0.005 로 고정하고 **밝기 L 만 움직여** 만든다. 균등한 L 간격(0.072)은 '체감 균등' 을 주지만 UI 에는 바탕 쪽에 촘촘한 단계가 더 필요하므로, 실제 토큰은 Radix 식 '역할별' 12단을 쓴다. 측정한 고급 사이트의 '종이 흰색'은 모두 **OKLCH L 0.97~0.99 · C 0.001~0.010** 범위다 — 눈에 '색'으로 읽히는 순간(FT 의 C 0.022) 그것은 브랜드 선언이 된다.

### Cited Findings
- HSL 은 "모든 색상에 같은 채도가 있다고 가정" 하지만 실제 화면과 눈은 색상마다 최대 채도가 달라 "밝기 10% 를 더하면 파랑과 보라에서 결과가 다르다"; 색상을 바꾸면(예: 브랜드색에서 오류 빨강 만들기) 밝기도 바뀌어 글자가 안 읽힐 수 있다. OKLCH 는 "눈에 일관된 밝기" 를 주어 변환 뒤 밝기를 예측할 수 있고 P3 광색역도 표현한다. 2025년 8~9월 기준 모든 최신 브라우저가 `oklch()` 지원 — [Evil Martians, OKLCH in CSS](https://evilmartians.com/chronicles/oklch-in-css-why-quit-rgb-hsl)
- OKLab 의 설계 목표: 밝기·채도·색상을 잘 예측하고 세 축이 "직교로 지각되어 하나를 바꿔도 나머지가 안 변한다". HSV 는 "노랑·자홍·청록이 빨강·파랑보다 훨씬 밝게 보인다", CIELAB 은 파랑에서 색상이 틀어진다. 흰색과 섞을 때 CIELAB·HSV 는 보라로 틀어지지만 OKLab 은 고르다(2020-12-23) — [Björn Ottosson, A perceptual color space for image processing](https://bottosson.github.io/posts/oklab/)
- Linear 는 HSL → LCH 로 바꾸고 테마 변수를 **98개 → 3개(바탕색·강조색·대비)** 로 줄였다. "LCH 는 지각적으로 균일해서 밝기 50 인 빨강과 노랑이 눈에 비슷하게 밝다"; 계산에 들어가는 파랑(chrome)을 제한해 "더 중립적이고 오래가는 인상" 을 얻었고, 대비 변수로 고대비 테마를 자동 생성한다 — [Linear, How we redesigned the Linear UI](https://linear.app/now/how-we-redesigned-the-linear-ui)
- Radix 12단의 역할: 1–2 앱 바탕, 3–5 컴포넌트 바탕(보통·hover·눌림/선택), 6–8 테두리(비대화형·대화형·강한 테두리/포커스 링), 9–10 단색 채움, 11–12 글자(저대비·고대비). "11·12단은 같은 스케일 2단 바탕 위에서 **APCA Lc 60 · Lc 90** 이 보장된다" — [Radix Colors, Understanding the scale](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)
- Radix **sand**(따뜻한 회색) 라이트 12단: `#fdfdfc #f9f9f8 #f1f0ef #e9e8e6 #e2e1de #dad9d6 #cfceca #bcbbb5 #8d8d86 #82827c #63635e #21201c`; 다크: `#111110 #191918 #222221 #2a2a28 #31312e #3b3a37 #494844 #62605b #6f6d66 #7c7b74 #b5b3ad #eeeeec` — [@radix-ui/colors 3.0.0 sand.css](https://cdn.jsdelivr.net/npm/@radix-ui/colors@3.0.0/sand.css) · [sand-dark.css](https://cdn.jsdelivr.net/npm/@radix-ui/colors@3.0.0/sand-dark.css)

### Inferences
- **방법(권장)**: ① 양 끝을 고정(`#f9f8f6` = L 0.979, `#141414` = L 0.191). ② 색상각 85° 고정, C 는 0.003(끝)~0.005(가운데)로 가운데를 약간 부풀리고 먹 쪽 세 단계에서 0 으로 줄인다(Radix sand 가 가운데에서 가장 따뜻한 것과 같은 모양). ③ L 을 정한 뒤 sRGB 안으로 채도만 깎아 넣고 hex 로 굳힌다. ④ 각 단계의 WCAG·APCA 를 표로 박제한다.

### Gaps
- Economist·Aesop·Stripe Press(현재 다크 `#201819` 만 확인)·Bloomberg 의 밝은 바탕 hex 는 봇 차단으로 재지 못했다. Aesop 을 흔히 `#fffef2` 로 말하지만 확인하지 못했다.
- '체감 균등' 을 사람 실험으로 검증한 KOSAI 자체 자료는 없다 — OKLab L 의 지각 균일성(Ottosson)에 기대는 것이다.

## 2. 강조색 — 하나를 둘 것인가, 거부할 것인가

### Takeaway
실측한 '조용한 고급' 제품들은 **강조색 면적이 1% 안팎**이다(Linear 0.0~0.8%, Vercel 0.1~0.4%, Mercury 약 0.9%). 반대로 Stripe(첫 화면 36%)·Robinhood(14~27%)는 색을 브랜드의 목소리로 쓴다 — 둘 다 '종이' 방향이 아니다. KOSAI 는 빨강·파랑을 이미 **등락 의미**에 썼기 때문에 세 번째 유채색은 무엇이든 의미 충돌(빨강 계열 = 상승, 파랑 계열 = 하락, 초록 = 서구식 상승·'성공')을 만든다. 결론: **유채색 강조색은 두지 않고, 먹(ink)이 강조색 역할**을 한다(헌장 2.3 A 와 같음). 굳이 하나라면 로고·인쇄물 전용의 어두운 병록색 `#154433` 정도이며 UI 에는 넣지 않는다.

## 3. 등락색 — 한국식 빨강↑/파랑↓의 정확한 값, 색각이상, 색 아닌 단서

### Takeaway
한국 대형 서비스들의 등락색은 **밝기 L 0.58~0.64 의 원색**(Toss `#f04452`/`#3182f6`, 네이버 `#ed3738`/`#007eff`, 업비트 `#dd3c44`/`#1375ec`)이라 흰 바탕 글자로는 **3.5~4.1:1 로 WCAG AA(4.5:1) 미달**이다. - 한국식 빨강–파랑은 서구식 빨강–초록보다 색각이상에 **구조적으로 안전하다**(deutan ΔE 26.8 vs 5.5). 이것은 영문 모드에서도 빨강 상승을 유지할 근거 하나가 된다(헌장 2.5 A) — 초록/빨강으로 뒤집으면 가장 흔한 색각이상(제2색맹)에게 둘이 거의 같아진다.

## 4. 대비 — WCAG 2.2 와 APCA 로 본 먹의 알파 사다리와 괘선

### Takeaway
법적·실무 기준은 여전히 **WCAG 2.x(본문 4.5:1, 큰 글자 3:1, 비텍스트 3:1)** 이고, APCA 는 글자 크기·굵기·극성(라이트/다크)을 반영하는 보조 판정기로 쓴다. 이 기준으로 먹 `#141414` 알파는 **.72(7.15:1 · Lc 82)** 가 보조 글자에 적당하고, 메타 글자는 **.60 이 WCAG 하한(4.72:1)** 이다 — 스테이징의 `--ink-55`(4.01:1)는 24px 미만 글자에 쓰면 AA 위반이다. 괘선 `.08`(1.18:1, Lc 8)은 장식선으로는 합법이지만 APCA 가 말하는 '식별 가능' 하한(Lc 15)보다 낮다 — 구조를 나타내는 선은 `.14`(Lc 16) 이상.

### Cited Findings
- WCAG 2.2 1.4.3: 본문 4.5:1, 큰 글자(18pt ≈ 24px, 또는 굵은 14pt ≈ 18.67px) 3:1 — [W3C, Understanding 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- WCAG 2.2 1.4.11: 컨트롤 식별에 필요한 시각 정보와 이해에 필요한 그래픽은 인접색과 3:1. **비활성 컨트롤 · 장식용 그래픽은 제외**. "컨트롤에 충분한 대비의 글자·아이콘이 있으면 경계 테두리는 필요 없다". 포커스 표시는 3:1 — [W3C, Understanding 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

### Inferences
- **알파 vs 단색 hex**: 알파는 흰 표면(`#fff`)·눌린 표면·등락 칩 위에서도 같은 '농도' 를 유지해 계층이 많은 UI 에 유리하다(α .72 가 흰 위 7.36, 바탕 위 7.15 로 거의 같다). 단, 유채색 칩 위에서는 칩 색을 물려받는다. 본문 `--ink` 는 단색, 보조·메타만 알파가 합리적이다(추정).
- '한글은 획이 많아 회색에서 빨리 흐려진다' 는 헌장의 관찰(계량 자료 없음) → 메타를 .60 이 아닌 **.62(5.05:1)** 로 여유를 두는 근거로만 쓴다(추정).

### Gaps
- APCA 는 WCAG 3 의 후보일 뿐 규범이 아니다. WCAG 3 의 최종 대비 방식은 확인하지 못했다(이 조사에서 W3C WCAG 3 초안을 열지 않았다).
- 한국 KWCAG 2.2 의 대비 조항 원문은 이번에 확인하지 않았다(WCAG 2.x 와 같은 4.5:1 로 알려져 있으나 미확인).

### Takeaway
`#0d0d0e`(OKLCH 0.160 0.002 286°)는 Material `#121212`(0.18)보다 어둡고 Linear `#08090a`(0.139)보다 밝은, 현재 고급 제품군의 전형적 '거의 검정' 이다. 다크의 규칙은 셋이다. ① **층은 그림자가 아니라 밝기**로 — 바탕 위 표면을 ΔL 0.03~0.04 씩 올린다(`#161617` → `#1d1d1f` → `#252527`). ② **순백 금지**, 본문은 `#ececea`(16.4:1, Lc 95). ③ **알파를 라이트와 똑같이 옮기지 않는다** — 같은 α 라도 다크에서 APCA 가 훨씬 낮게 나오므로(α .72: 라이트 Lc 82 ↔ 다크 Lc 58) 보조 글자는 α .84, 메타는 α .66 으로 올린다. 유채색은 L 을 올리고 C 를 낮춘다(4장·3장).

## 6. 색 심리·신뢰·럭셔리 코드·유행 — 무엇이 오래가고 무엇이 벌써 낡았나

### Takeaway
색 심리는 '파랑 = 유능·신뢰, 빨강 = 흥분' 정도가 실험으로 지지되고, **채도·명도가 그 신호의 세기**를 정한다(Labrecque & Milne). 고급 코드는 특정 색상이 아니라 **낮은 채도 · 먹의 색온도 · 넓은 무채색 면적**이다. 2026 Pantone 이 처음으로 흰색(Cloud Dancer `#F0EEE9`)을 골랐다는 것은 '따뜻한 흰 종이' 가 지금의 시대 코드라는 뜻이자, 곧 흔해질 위험 신호다. KOSAI 의 `#f9f8f6` 은 Cloud Dancer 보다 밝고 채도가 절반 이하(C 0.003 vs 0.007)라 '유행 색' 으로 읽히지 않는 쪽에 있다.

### Cited Findings
- 파랑은 유능함·신뢰성, 빨강은 흥분과 대응; 채도와 명도(선명/탁함, 밝음/어두움)가 성격 신호를 키우거나 줄인다; 색은 브랜드 성격 인식을 거쳐 구매 의향·호감에 간접 영향(4개 연구) — [Labrecque & Milne 2012](https://link.springer.com/article/10.1007/s11747-010-0245-y) · [ResearchGate 사본](https://www.researchgate.net/publication/251277565_Exciting_red_and_competent_blue_the_importance_of_color_in_marketing)
- Pantone 2026 올해의 색 **PANTONE 11-4201 Cloud Dancer** — "평온함을 품은 흰색", "빈 캔버스처럼 새 출발의 욕구" — [Pantone 보도자료](https://www.pantone.com/articles/press-releases/pantone-announces-color-of-the-year-2026-cloud-dancer); 화면 근사값 `#F0EEE9`, 흰색 계열 최초 선정(2차) — [Color Picker Lab](https://colorpickerlab.com/colors/color-of-the-year-2026)
  - 실측(계산): `#F0EEE9` = OKLCH 0.949 0.0070 89° — KOSAI 바탕보다 L 0.03 어둡고 채도 2.4배.
- Pantone 2025 **17-1230 Mocha Mousse**(부드러운 갈색, "사려 깊은 탐닉") — [Pantone 보도자료](https://www.pantone.com/articles/press-releases/pantone-announces-the-color-of-the-year-2025-pantone-17-1230-mocha-mousse-brought-to-life)
- 럭셔리·편집 사이트 실측(사이트): Jil Sander body `#fbfbf6`, 글자 `#000`; The Row 글자 `#1c1b1b` on `#fff`(선명한 색 면적 2.2%, 나머지 유채색은 사진); Mercury `#f6f5f2`. Hermès·Celine·Bottega·Loro Piana 는 봇 차단 — [jilsander.com](https://www.jilsander.com/en-us) · [therow.com](https://www.therow.com) · [mercury.com](https://mercury.com)

### Inferences
- **이미 낡은 것**: 색상각 265~290° 의 인디고·보라(특히 그라데이션), 네온 라임(Robinhood `#ccff00` 류 — 브랜드 자산으로는 강하지만 따라 하면 모방), 글로우. **곧 낡을 위험**: Cloud Dancer·Mocha Mousse 처럼 채도 0.007 이상의 크림·모카 바탕(유행의 한가운데). **오래가는 것**: C < 0.005 의 거의 무채 종이 + 먹, 색은 의미(데이터)에만.
- '파랑 = 신뢰' 자리는 KOSAI 에서 이미 하락이 차지했다. 신뢰 신호는 색상이 아니라 **대비의 정직함(AA 이상)·숫자 정렬·출처 표기**로 낸다(추정).
- 색 심리 연구는 대부분 서구 표본이고 효과 크기가 맥락 의존적이다 — '빨강 = 위험' 도 한국 증시 화면에서는 '빨강 = 상승·좋음' 으로 뒤집힌다(3장 관례). 일반 색 심리를 그대로 옮기지 않는다(추정).

### Gaps
- 한국 금융 이용자의 색-신뢰 인식에 대한 실험 연구는 찾지 못했다.
- Pantone 은 공식 페이지에 sRGB hex 를 싣지 않아 `#F0EEE9` 는 2차 자료 값이다.

## 7. 도구와 CSS — 한 층의 의미 토큰으로 라이트·다크를 같이 몬다

### Takeaway
설계는 OKLCH 도구(Leonardo·Radix·Huetone·OKLCH picker)로 하고, 배포는 **hex 로 굳힌 원시값 + 의미 토큰 한 층**으로 한다. `color-mix()`·상대 색 문법은 이제 주요 브라우저에서 쓸 수 있지만, 핵심 대비값(글자·등락)은 계산된 hex 로 박제해 검사기가 확인할 수 있게 두고, 파생(hover·옅은 배경)에만 쓴다.

### Cited Findings
- Adobe **Leonardo**: 목표 대비비(바탕 대비 몇 :1)로 색 단계를 생성, 밝기로도 지정 가능; JS 모듈 `@adobe/leonardo-contrast-colors` 와 웹 UI; 출력은 JS 파라미터·CSS 변수·W3C 초안 형식 디자인 토큰(각 색의 대비비와 사용 주석 포함) — [GitHub adobe/leonardo](https://github.com/adobe/leonardo) · [leonardocolor.io](https://leonardocolor.io/)
- **Radix**: 12단 역할 + 11·12단 APCA Lc 60/90 보장(1장) — [Radix](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)
- Evil Martians 가 소개하는 도구: OKLCH Color Picker(oklch.com), **Huetone**(팔레트 생성), OkColor(Figma), Color.js·culori(JS) — [Evil Martians](https://evilmartians.com/chronicles/oklch-in-css-why-quit-rgb-hsl)
- Realtime Colors: 팔레트를 실제 레이아웃에 얹어 보는 도구 — [realtimecolors.com](https://www.realtimecolors.com)
- 상대 색 문법(`oklch(from var(--x) calc(l - .1) c h)`): Chrome/Edge 119+, Firefox 128+(2024-07), Safari 16.4+; `color-mix()`: Chrome/Edge 111+, Firefox 113+, Safari 16.2+ (2차 가이드) — [Relative Color Syntax, Dev Guides](https://camoa.github.io/dev-guides/css/modern-css/relative-color/) · [MDN, Using relative colors](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_colors/Relative_colors)

### Inferences
- **토큰 구조(권장, 추정)** — 원시값은 모드별 hex, 의미 토큰은 한 이름:

```css

  --hair:rgba(20,20,20,.08); --line:rgba(20,20,20,.14); --line-strong:rgba(20,20,20,.46);
  --up:#c8102e; --down:#1e5fbf; --flat:var(--ink-3);
  --up-bg:rgba(200,16,46,.08); --down-bg:rgba(30,95,191,.08);
}
:root[data-theme=dark]{
  --bg:#0d0d0e; --surface:#161617; --surface-2:#1d1d1f; --surface-3:#252527;
```

  `color-mix(in oklab, var(--ink) 4%, var(--bg))` 하나로 라이트는 어두워지고 다크는 밝아지는 hover 가 된다.
- 검사기(`scripts/patch_light_palette.py --check` 계열)에 **대비 표를 박제**해, 토큰을 바꾸면 WCAG 4.5:1(글자)·3:1(`--line-strong`, 포커스)을 자동 확인하는 것이 '기억 대신 검사' 원칙(CLAUDE.md)에 맞다(추정).

## KOSAI 적용 제안

우선순위 순. 모든 수치는 이 문서의 실측(계산) 표에서 왔다.

1. **[필수] 라이트 메타 글자 α .55 → .62** (`rgba(20,20,20,.62)` = `#6b6b6a`): 4.01:1 · Lc 65 → **5.05:1 · Lc 73**. 지금 값은 24px 미만 글자에서 WCAG 1.4.3 AA 미달이다. 생성기 소스에 `color:var(--ink-55)` 가 107곳 있다(실측, grep).
2. **[필수] 다크 등락 `#f0655f`/`#6f9cf5` → `#ff908a`/`#81b7ff`** (OKLCH 0.77 · C 0.135/0.119 · 24°/256°): WCAG 6.23/7.17 → **8.89/9.39**, APCA Lc 44/49 → **59/62**. NN/g 의 '채도 높은 파랑 번짐' 과 APCA 의 다크 과대평가 문제를 함께 푼다. 칩 배경은 같은 색 α .12.
3. **[필수] 다크 보조·메타 알파를 올린다**: `--ink-72` → **.84**(`#c8c8c7`, 11.6:1 · Lc 73), `--ink-55` → **.66**(`#a0a09f`, 7.4:1 · Lc 51), `--ink-30` → **.40**(3.4:1). 라이트와 같은 α 를 쓰면 다크 위계가 APCA 로 Lc 58/38 까지 떨어진다.
4. **[필수] 등락은 색 + 부호(+/−, U+2212) + ▲▼ 세 겹** 유지. 제1색맹(남성 5.9% 중 일부)에게 `#c8102e` 는 `#544c2d` 올리브 먹으로 보인다.
5. **라이트 등락 `#c8102e`/`#1e5fbf` 는 그대로 둔다.** 5.54/5.74:1 · Lc 73/76 · 상승–하락 ΔL 0.029 · 색각이상 ΔE ≥ 23. L 을 맞춘 대안 `#be2323`/`#1c65c8` 과의 차이는 ΔE ≈ 2.5 로 바꿀 이득이 없다. Toss·네이버·업비트의 원색(3.5~4.1:1)을 따라가지 않는다.
6. **영문 모드도 빨강 상승 유지**: 빨강–파랑 쌍은 제2색맹 ΔE 26.8, 서구식 빨강–초록은 5.5. 뒤집으면 가장 흔한 색각이상에게 둘이 거의 같아진다.
7. **유채색 강조색은 두지 않는다**(헌장 2.3 A 지지). 옥스블러드는 상승과 7°, 남색은 하락과 4° 차이로 의미가 섞이고, 사프란은 2.07:1 로 글자 불가, 초록은 서구식 상승·성공색과 겹친다. 위계는 먹 농도 1 / .72 / .62 + 굵기 + 세리프 제목으로. 색상각 265~290° 인디고·보라와 그라데이션은 어떤 자리에도 쓰지 않는다('AI 기본색' 대역).
8. **따뜻한 무채 사다리를 hex 로 박제**: `#f9f8f6 · #ffffff · #f2f1ee · #ebe9e6 · #e3e2de · #dcdad7 · #d0cecb · #a09e9b · #81807d · #706e6b · #535250 · #141414` (색상각 85°, C ≤ 0.005). 메타 단색이 필요하면 `#706e6b`(4.79:1) 이상.
9. **입력칸 테두리 `--line-strong` 은 먹 기준 α .46 이상**(`#908f8e`, 3.00:1). 헌장의 `rgba(0,0,0,.44)`(3.21:1)를 먹 `#141414` 로 옮기면 2.87:1 로 미달한다. 다크는 흰 α .40(3.80:1).
10. **괘선 두 등급**: 라이트 `--hair .08`(1.18:1, 표 행·장식 — 1.4.11 면제) · `--line .14`(1.34:1 · Lc 16, 절 구분 등 구조). 다크는 NN/g '사라지는 구분선' 대비 `--hair` 를 흰 .08 → **.10**, `--line` .14 → **.16**.
11. **다크 표면 사다리**: `#0d0d0e`(L 0.160) → `#161617`(0.201) → `#1d1d1f`(0.232) → `#252527`(0.265) → `#2e2e30`(0.302). 그림자 대신 ΔL 0.03~0.04 로 층을 만든다. 다크 표면에는 85° 틴트를 넣지 않고 바탕과 같은 286°·C ≤ 0.004(진흙색 방지).
12. **옅은 등락 배경 상한 α .08(라이트)**: 하락 글자가 α .10 에서 4.60, .12 에서 4.47:1 로 떨어진다. 다크는 .12~.16 까지 괜찮다(6.9~7.8:1).
13. **포커스 링**: 비텍스트 3:1 만 넘기면 된다 — 라이트 `#0d69d4`(4.96:1) 또는 먹 `#141414`(17.4:1) 2px, 다크 `#88bafd`(9.70:1). 헌장대로 파랑을 쓰면 등락 숫자와 겹치지 않도록 링(선)에만.
14. **토큰은 의미 한 층 + 모드별 hex**, 파생(hover·칩)만 `color-mix(in oklab, …)` 로. 대비 표를 검사기에 박제해 WCAG 4.5:1·3:1 을 자동 확인한다(기억 대신 검사).
15. **유행 색을 들이지 않는다**: Cloud Dancer `#F0EEE9`(C 0.007)·Mocha Mousse 계열 크림·모카 바탕, 네온 라임, 글로우. KOSAI 바탕 `#f9f8f6`(C 0.003)은 이미 '유행 밖의 따뜻함' 에 있다 — 바꾸지 않는다.
