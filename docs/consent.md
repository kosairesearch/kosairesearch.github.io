# 가입 동의 — 무엇을 받고 어디에 남기나

## 왜 이렇게 만들었나

전에는 체크박스 하나였다.

```
☑ 만 14세 이상이며, 이용약관 및 개인정보처리방침에 동의합니다.
```

두 가지가 잘못돼 있었다.

**세 항목이 하나로 묶여 있었다.** 개인정보보호법은 동의받을 항목을 구분해 각각
받도록 한다. 하나만 동의할 방법이 없었다.

**'개인정보처리방침에 동의'는 형식이 어긋난다.** 처리방침은 회사가 일방적으로
공개하는 문서이지 동의를 받는 대상이 아니다. 동의는 무엇을 수집해 어디에 쓰고
얼마나 보관하는지를 그 자리에서 보여주고 받아야 한다.

그리고 더 큰 구멍이 있었다. **가입 페이지는 동의를 요구했는데 로그인 페이지로
들어오면 아무 동의 없이 계정이 만들어졌다.** 카카오·네이버 로그인은 계정이
없으면 그 자리에서 만들기 때문이다.

## 동의를 받는 시점 — 가입 수단별

구글·카카오·네이버는 **각자 자기 동의 화면을 이미 보여 준다.** 확인한 방법:

| | 확인한 곳 | 결과 |
|---|---|---|
| 카카오 | accounts.kakao.com → 연결된 서비스 관리 | KOSAI 있음 (연결일자 2026-06-06, 이용정보 [필수] 닉네임) |
| 구글 | myaccount.google.com/connections | KOSAI 있음 |
| 네이버 | `authorize` 에 `auth_type=reprompt` 를 붙여 강제 호출 | 동의 화면 뜸 |

이 화면들은 **사람마다 앱마다 한 번만** 뜬다. 이미 동의한 사람에게 또 물으면
로그인할 때마다 성가시기 때문이다. 그래서 개발 중에 여러 번 로그인해 본
사람에게는 안 보인다 — 없는 것이 아니다.

그 위에 우리 동의 화면을 한 번 더 얹으면 같은 것을 두 번 묻는 셈이다.
그래서 소셜 경로는 **버튼 아래 한 줄 고지**로 받는다.

> 가입하면 [이용약관]과 [개인정보처리방침]에 동의하며, 만 14세 이상임을 확인합니다.

| 수단 | 어디서 받나 | 기록되는 `method` |
|---|---|---|
| 카카오 | 카카오 동의 화면 + 버튼 아래 고지 | `signup-notice` |
| 네이버 | 네이버 동의 화면 + 버튼 아래 고지 | `signup-notice` |
| 구글 | 구글 동의 화면 + 버튼 아래 고지 | `signup-notice` |
| 이메일 | 가입 폼의 체크박스 4개 | `checkbox` |

이메일 가입만 체크박스가 남는다. 그 길에는 동의를 보여 줄 자리가 거기밖에
없기 때문이다. 문구는 `consent.js` 한 곳에서 만든다.

무엇을 보고 눌렀는지 나중에 답할 수 있어야 하므로 판 번호(`version`)와
방식(`method`)을 같이 남긴다.

### 기록하는 자리

계정이 만들어지는 바로 그 자리에서 남긴다. 지나간 뒤에 붙잡지 않는다.

- 카카오·네이버 — `socialLogin` 이 계정을 만들면서 같은 호출 안에서 쓴다.
  쓰기에 실패하면 방금 만든 계정도 지운다.
- 구글 — 팝업이 닫히고 `isNewUser` 면 그 자리에서 쓴다.
- 이메일 — 계정을 만든 직후, 로그아웃하기 전에 쓴다(로그아웃 뒤에는 본인
  문서에 쓸 권한이 없다).

전에는 `auth-state.js` 가 모든 페이지에서 동의 기록 없는 계정을 붙잡아
화면을 띄웠다. 네 길 모두 그 자리에서 남기게 됐으므로 그 그물은 걷어냈다.

### 카카오싱크를 붙이면

카카오 개발자 콘솔에 우리 약관을 등록하면 카카오 동의 화면에서 서비스
약관까지 한 번에 받는다. 지금의 한 줄 고지를 카카오 화면이 대신하게 된다.

신청·심사와 콘솔 설정이 필요하고, 사업자 정보가 있어야 한다.

## 지금 받는 것

| 항목 | 구분 | 키 |
|---|---|---|
| 만 14세 이상 | 필수 | `age14` |
| 이용약관 동의 | 필수 | `terms` |
| 개인정보 수집·이용 동의 | 필수 | `privacy` |
| 마케팅 정보 수신 동의 | **선택** | `marketing` |

선택 항목은 기본이 꺼져 있고, 동의하지 않아도 가입된다. 이게 지켜지지 않으면
선택 동의가 아니다.

**마케팅은 가입할 때 받지 않는다.** 소셜 경로에는 체크박스가 없는데, 선택
항목을 한 줄 고지에 묻어 두면 그건 선택 동의가 아니기 때문이다. 가입 뒤
설정 페이지에서 켠다(→ 철회).

문구와 화면은 `consent.js` 한 곳에 있다. 이메일·구글·카카오·네이버 네 경로가
모두 이 파일을 쓰므로 문구가 갈라지지 않는다.

## 어디에 남나

`users/{uid}` 문서.

```js
{
  consents: {
    version:   "2026-08-20",   // 동의서 판 번호
    agreedAt:  <서버시각>,
    age14:     true,
    terms:     true,
    privacy:   true,
    marketing: false           // ← 선택
  },
  marketingAt:  <서버시각>|null, // 마케팅 동의를 켠 시각
  signupMethod: "email"|"google"|"kakao"|"naver",
  createdAt, updatedAt
}
```

본인만 읽고 쓴다(`firestore.rules`). 탈퇴하면 이 문서도 지운다 — 동의 화면에서
"보유 기간: 회원 탈퇴 시까지"라고 알리고 받았기 때문이다. 클라이언트와 서버
양쪽에서 지운다(창을 닫아 버리면 클라이언트 쪽이 안 돌기 때문).

### 이메일을 왜 여기에도 두나

마케팅 메일을 보내려면 주소가 있어야 하는데, **소셜 가입자는 Firebase Auth 에
이메일이 없다.**

| 가입 경로 | Firebase Auth | `users/{uid}` |
|---|---|---|
| 이메일 | 있음 | 있음 |
| 구글 | 있음 | 있음 |
| 네이버 | **없음** | 있음 |
| 카카오 | **없음** | **없음** — 카카오가 안 준다 |

네이버는 이메일을 주는데 `socialLogin` 이 커스텀 토큰 클레임으로만 넘기고
버렸다. "계정 충돌이 무섭다" 는 이유였는데, 충돌은 Firebase 사용자에 이메일을
심을 때 나는 것이지 우리 문서에 적어 두는 것과는 상관이 없었다. 그래서
`users/{uid}.email` 에 남긴다.

**카카오는 지금 닉네임만 준다.** 개발자 콘솔의 동의항목에 이메일이 없다.
켜기 전까지 카카오 가입자에게는 마케팅 메일을 보낼 수 없다. 켜면 그 다음
로그인 때 채워진다 — `socialLogin` 이 이메일이 오면 갱신하되, 없다고 해서
이미 있는 값을 지우지는 않는다.

## 마케팅 동의자 골라내기

이게 이 문서의 핵심이다. 동의한 사람에게만 보내야 하고, 아닌 사람에게 보내면
법을 어긴다.

**Firebase 콘솔에서 바로**

Firestore → `users` 컬렉션 → 쿼리 추가:

```
consents.marketing  ==  true
```

**스크립트로 (관리자 권한 필요)**

```js
// 마케팅 수신 동의자 이메일 목록
const admin = require("firebase-admin");
admin.initializeApp();

const snap = await admin.firestore()
  .collection("users")
  .where("consents.marketing", "==", true)
  .get();

const rows = snap.docs.map(d => ({ uid: d.id, ...d.data() }));
const sendable = rows.filter(r => r.email);
const noEmail  = rows.filter(r => !r.email);

console.log(sendable.map(r => r.email).join("\n"));
if (noEmail.length) {
  // 대부분 카카오 가입자다. 동의는 했는데 보낼 주소가 없다.
  console.warn(`주소 없음 ${noEmail.length}명:`,
    noEmail.map(r => `${r.uid}(${r.signupMethod})`).join(", "));
}
```

주소가 없는 사람이 나오면 그건 우리 잘못이지 그 사람 잘못이 아니다.
카카오 이메일 동의항목을 켜서 채워 넣어야 한다.

## 문구를 고칠 때

`consent.js` 의 `CONSENT_VERSION` 을 올린다. 올리면 기존 회원도 다음 로그인
때 새 동의를 한 번 받는다.

오탈자 수정 정도로는 올리지 않는다. **받는 내용이 실제로 바뀔 때만** 올린다 —
수집 항목이 늘거나, 이용 목적이 바뀌거나, 보유 기간이 달라질 때.

## 철회

동의는 언제든 철회할 수 있어야 한다. 켜는 길만 있고 끄는 길이 없으면 그건
동의가 아니다.

헤더의 계정 메뉴 → **마케팅 수신 설정**. 켜고 끄면 이렇게 남는다.

| | 켤 때 | 끌 때 |
|---|---|---|
| `consents.marketing` | `true` | `false` |
| `marketingAt` | 그 시각 | `null` |
| `marketingOffAt` | `null` | 그 시각 |

언제 동의했고 언제 철회했는지를 나중에 답할 수 있어야 하므로 두 시각을
따로 남긴다.

**메일에 수신거부 링크는 아직 없다.** 마케팅 메일을 실제로 보내기 시작할 때
본문에 넣어야 한다 — 앱에 들어와야만 끌 수 있는 것으로는 부족하다.

가입 확인·비밀번호 재설정처럼 거래에 필요한 메일은 동의 없이 보낼 수 있고
수신거부 대상도 아니다.

## 확인해 둘 것

여기 적힌 것은 일반적으로 알려진 기준을 따라 만든 것이지 법률 자문이 아니다.
결제 기능을 넣기 전에 문구와 항목 구성을 한 번은 전문가에게 확인받는 것이 좋다.
