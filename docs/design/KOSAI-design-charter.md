# KOSAI 디자인 헌장

*v1.2 · 2026-09-24 · 디자인 총괄 정리 — 세 비평(취향 · 구현 가능성 · 사실 검증)을 반영한 판. 무엇을 어떻게 고쳤는지는 끝의 '12. 반영 기록' 에 있다.*

이 문서는 12개 분야 조사(타이포그래피 · 색 · 레이아웃 · 신뢰 · 데이터 읽기 · 랜딩 · 모션 · 접근성 · 트렌드 · 내비게이션 · 한국 사용자 · 완성도)와 저장소의 현재 상태(34장 인라인 CSS, `stock.html` 13개 절, `CLAUDE.md` 규칙), 그리고 오늘(9/24) 대표가 이미 내린 결정(헤더 상자 제거·라이트 팔레트 `#f9f8f6`/`#141414`·푸터 면책 상자 제거·페이저 상자 제거)을 한 벌로 묶은 것이다.

읽는 법.

- **뼈대**는 손대지 않는다. **옷**만 바꾼다(1장).
- 대표가 정해야 하는 것은 2장에 선택지와 추천을 같이 적었다. 추천은 근거가 있고, 근거가 없는 것은 **취향**이라고 표시했다.
- 값은 전부 계산하거나 실측했다. 대비 수치는 이 세션에서 WCAG 공식으로 직접 계산한 것이다(`scratchpad/design/color_calc.py`). v1.1 에서 알파 토큰의 대비를 **바탕에 합성한 뒤** 다시 계산해 표를 고쳤다(3.1).
- 비평이 확인하지 못한 주장은 **확인 필요** 라고 적었다. 그 항목은 실행 전에 누군가 확인해야 한다.
- 우선순위: **필수**(AI 티·접근성 미달·모순을 없애는 것) → **권장** → **선택**.

## 0. 한 줄 방향

> **KOSAI 는 종이에 인쇄된 리서치 리포트처럼 보여야 한다 — 따뜻한 흰 종이, 먹색 글자, 줄 맞춰 선 숫자. 장식은 없고, 정돈이 격을 만든다.**

대표의 말("깔끔하고 세련되고 고급스러운, 신뢰를 주는, 너무 화려하지 않되 적당히 화려한, 해외 금융 웹사이트 수준")을 한 문장으로 옮기면 위와 같다. Public · Mercury · Stripe · Wealthsimple 네 곳이 실제로 공유하는 것은 색이나 글꼴이 아니라 **밝은 바탕 · 무채색 90% · 강조색 하나 · 넓은 여백 · 정확한 타이포 · 실물(제품 화면)** 이라는 뼈대였고(조사 2·3·6·9), "적당히 화려한" 자리는 **세리프 제목과 리포트 제호(4.0) 한 곳, 그리고 정지된 2D 브랜드 마크(프리즘의 후신, 2.4) 한 곳**으로 한정한다.

이것을 떠받치는 원칙 셋.

## 2. 결정 사항 — 대표가 정할 것

각 항목은 **선택지 → 추천 → 근거** 순이다. 추천대로 가면 3장 이후의 값이 그대로 성립하고, 다른 선택지를 고르면 어디가 달라지는지 적어 두었다.

### 2.1 밝은 기본 vs 어두운 기본

| 선택지 | 내용 |
|---|---|
| **A (추천)** | 첫 방문 = 라이트. 저장값(`kos-theme`)이 있으면 그것을 따른다. OS 다크 설정은 따르지 않는다. 랜딩도 라이트. |
| B | 첫 방문 = OS 설정(`prefers-color-scheme`), 없으면 라이트. |
| C | 지금처럼 다크 기본(비추천). |

**추천 A.** 근거: NN/g(Piepenbrock 실험) — 정상 시력자는 라이트에서 시력·교정 과제 성적이 높고 글자가 작을수록 격차가 커진다(우리 표 숫자 13~15px 가 바로 그 구간). 참고 4사 흰 바탕. 국내 금융 UI 전부 흰 바탕 기본. 어두운 남색 기본은 대표가 비추천한 Linear·Vercel 의 첫 번째 지문(조사 9·10). A 와 B 의 차이는 '브랜드가 종이인가, 이용자 설정이 우선인가' 인데, 랜딩·리포트·브리핑이 "종이 리포트" 로 읽히려면 첫인상이 흰 종이여야 한다(50ms 첫인상, NN/g). **B 는 취향의 문제**라 대표가 골라도 3장 값은 그대로다.

### 2.7 글꼴을 어디서 받나

**추천 jsDelivr.** `cdn.jsdelivr.net` 은 저장소가 이미 쓰는 곳(랜딩 three.js — 2.4 A 면 빠지지만 의존 자체는 새것이 아니다). GitHub Pages 는 모든 파일에 `max-age=600` 을 붙여 10분마다 재확인(304)하는데(`patch_header.py` 머리말의 '가끔 깜빡' 원인) jsDelivr 는 **npm 버전 고정 주소**(`npm/pretendard@1.3.9`)를 1년 캐시한다. 마루 부리는 다르다 — `gh/fonts-archive/MaruBuri` 저장소에는 태그·릴리스가 없어(data.jsdelivr `versions: []`) 태그 없는 gh 주소는 기본 브랜치를 가리키고, 캐시가 짧고 내용이 바뀔 수 있다. 그래서 **커밋 SHA 로 고정**한다: `gh/fonts-archive/MaruBuri@977eeff68d1d40bcef341f09c1f56cce1903bb8a/…`(2026-09-24 HEAD, `git ls-remote` 로 확인). 대안: 서브셋 조각(92조각 × 굵기)을 `fonts/` 에 복사해 자체 호스팅 — 파일 수백 개가 저장소에 들어오고 캐시가 짧다. 어느 쪽이든 정적 woff2·otf 10개(12MB)는 지운다.

### 2.8 다크 바탕 — 먹색 vs 남색

**추천 먹색 `#141414`.** 대표가 정한 라이트 먹색을 그대로 다크 바탕으로 쓰면 라이트·다크가 한 쌍(종이 ↔ 먹)이 되고, 남색 기울기(`#0e0e16`, OKLCH 색상각 284°)는 '개발자 SaaS' 인상이자 대표가 비추천한 룩이다(조사 9). Material·NN/g: 순검정 대신 `#121212` 급 진회색, 층은 그림자가 아니라 밝기 단계로. 남색을 고르면 3.1 의 다크 열만 바뀐다.

### 2.9 헤더 활성 표시

오늘 대표가 "상자 없이 글자만 밝고 굵게" 로 정했으므로 **그대로 둔다**(뼈대). NN/g 는 현재 위치 신호를 두 채널(색 + 위치)로 주라고 하지만, 시각 채널 하나 + 프로그램 채널(`aria-current="page"`) 로 WCAG 요건은 충족된다. 2px 밑줄 변형은 시안으로만 보여 주고 강제하지 않는다.

### 2.10 종목 리포트 데스크톱 구조

**유지 — 왼쪽 레일 목차(200px, sticky) + 본문.** 이미 구현돼 있고 NN/g 목차 지침(레일은 sticky, 오른쪽 레일은 무시됨, 현재 절 강조)과 맞는다. 본문 폭만 880 → 680 으로 좁히고 표는 880 까지 튀어나가게 한다(3.3).

### 2.11 숫자의 글리프 둘 — 마이너스와 빈값

**추천: 공통 글리프 규칙 둘 — 음수는 마이너스(U+2212, 하이픈 U+002D 아님), 빈값은 em dash(—, U+2014).** 숫자 표기는 뼈대지만 이것은 글리프 교체라 값이 변하지 않는다(Morningstar 규칙 · Butterick). 부호·빈값을 내는 포매터는 두 함수가 아니라 **7곳**이다: `stock.html`(`fwon`·`fpct`·`fpct2`·`fx`·`negc`) · `Reports`/`Watchlist` `KOS.pct` · `Home` `KOS.pct`·`pctPlain`·`ratio` · `industry.html` `pct()` · `render_brief.py`(브리핑 본문을 HTML 로 굽는 파이썬) · `generate_geo_pages.py`(r/ 정적 리포트). 빈값도 이미 갈려 있다(stock '—' vs Home·Reports '-'). 범위를 두 함수로 잡으면 표마다 기호가 섞여 나가므로 7곳을 한 릴리스에 같이 고치고, 검사는 새로 만든다(8장 #17 — 페이지 포매터를 jsdom 으로 불러 `−1.20%`·`—` 를 내는지). `number_spacing_test.py` 는 무관하니 손대지 않는다. 대표가 싫으면 그대로 둔다.

## 3. 토큰 사양

34장에 인라인 CSS 가 각각 박혀 있으므로 토큰 블록은 **한 스크립트(`scripts/patch_design_tokens.py`)가 심고 `--check` 가 지킨다.** 손으로 34번 고치지 않는다.

다만 '블록 하나를 더 얹는' `patch_header` 방식은 여기서 안 된다 — 34장의 `:root` 가 제각각이라서다(Home: `--n-10~900`·`--brand-violet`·`--shadow-glow`·`--font-mono`, stock: `--hair`·`--up-soft`·`--shadow-3` 와 302행의 두 번째 `:root`(차트 토큰), index: 옛 팔레트 `rgb(0,0,0)`/`rgb(242,243,250)`, `--up/--down` 은 12장만). 얹기만 하면 옛 `:root` 가 남아 '`--shadow-glow` 0건'·'`--fg-3` ≥ .60' 검사가 실패하고, `--pad` 중단점은 `:root` 밖 `@media` 3줄이 페이지마다 다르다. 그래서 **`patch_light_palette.py` 방식의 제자리 교체**다.

  ① 첫 `:root{…}` · `:root[data-theme="dark"]{…}` · `:root[lang="en"]{…}`(2.5 A 면 삭제) 블록을 새 블록으로 통째 교체
  ② `@media … :root{--pad:…}` 3줄을 페이지마다 다른 중단점(Home 1024→40px · industry 1280 · 나머지 1180)에서 **1180 하나**로 통일 교체(3.3)
  ③ 페이지 안 재정의(stock 302행 차트 토큰) 제거
  ④ 폐기 토큰 참조(`var(--border-2)` 220건 · `--brand-cyan` 88건 · `--radius-xl` 72건 — 실사이트+스테이징+JS, 2026-09-24 밤 실측)를 같은 실행에서 치환
  ⑤ `index.html` 포함(`patch_light_palette` 의 index 제외도 해제)

`--check` 는 블록 동일성 + 폐기 토큰 참조 0건을 함께 본다. 헤더 블록(`patch_header.py` HEAD)과 푸터 CSS(`patch_biz_footer.py` `CSS_BOX`)는 각자의 스크립트에서 토큰 값으로 고치고 실사이트 34장 + `staging/` 에 재실행한다(9장). JS 4종이 주입하는 CSS 는 HTML 만 도는 스크립트가 못 보므로 따로 고친다(2.1).

### 3.1 색

모든 색은 대표가 정한 두 값 — 바탕 `#f9f8f6` = OKLCH(0.979 0.003 85°) · 먹색 `#141414` = OKLCH(0.191 0 —) — 에서 나온다. 회색 램프는 같은 색상각(85°, 따뜻한 쪽)에 채도 0.003~0.006 으로 만들어 hex 로 굳혔다(Radix·Refactoring UI: 순수 회색은 생기가 없다, 세리프와는 따뜻한 회색이 어울린다). 글자·선은 지금처럼 **검정 알파 `rgba(0,0,0,α)`(농도)** 로 두어 흰 카드 위에서도 종이 바탕 위에서도 같은 규칙이 먹게 한다(`patch_light_palette.py` 의 "반투명 검정은 농도라 손대지 않는다" 와 같은 논리). v1 은 이 알파를 먹색 `rgba(20,20,20,α)` 로 적으면서 대비는 검정 기준으로 계산해 표가 틀렸다(먹색 .70 은 6.66:1, .62 는 5.05:1, .44 는 2.87:1 — 입력창 경계가 3:1 미달). 검정 알파로 두면 아래 표의 숫자가 그대로 맞고 육안 차이는 없다. 대비 계산은 언제나 **알파를 바탕에 합성한 뒤** 한다(8장 #2). 본문 글자는 알파가 아니라 `--fg-1` 실색이다.

한글 보정 규칙.

- 세리프 제목의 자간은 −0.01em 까지만(한글 명조는 조이면 획이 붙는다) — 위 표의 세리프 행이 전부 −0.01em 인 이유(v1 은 표가 −0.02em 이라 규칙과 어긋났다). Pretendard 제목은 −0.02em 이 하한.
- `clamp` 최대/최소 비율 ≤ 2.5(56/36 = 1.56, 30/24 = 1.25) — 확대 접근성(Smashing 2023).
- 모든 문단·셀: `word-break:keep-all; overflow-wrap:anywhere`(현재 `break-word` → `anywhere`, 긴 URL·영문 종목명). 제목 `text-wrap:balance`, 본문 `text-wrap:pretty`. 양쪽 정렬 금지.
- 숫자: `font-variant-numeric: tabular-nums lining-nums` 를 표·카드·등락·헤더 시세·목차 번호에.
- 세리프 안의 라틴: **세리프 글꼴의 라틴을 그대로** 쓴다(2.2). `unicode-range` 로 라틴만 Pretendard 로 바꾸는 트릭은 쓰지 않는다 — 'SK하이닉스'·'Samsung Electronics' 가 짜깁기가 된다. 숫자 종목 코드·날짜·시장 표시는 별도 요소(`.th-meta`·`.th-asof`)에만 Pretendard tabular.
- 다크 모드에서 같은 400 이 더 굵어 보이면 가변 굵기 380 을 검토 — 확인 못 함, 시안에서 비교.

| 대체 글꼴 | 본문: `@font-face{font-family:"Pretendard Fallback";src:local("Apple SD Gothic Neo"),local("Malgun Gothic");size-adjust:…;ascent-override:…}`. 세리프: `"Serif Fallback"` = `local("AppleMyungjo")`(macOS) · `local("Batang")`(Windows) · `local("Noto Serif CJK KR")` 에 `size-adjust`·`ascent-override` 실측 — 폴백도 명조라 교체 순간 인상이 바뀌지 않는다. iOS·안드로이드 기본기에는 시스템 명조가 없어 그 기기는 Pretendard 로 첫 그림이 된다(기기별 실측 — 확인 필요). 값은 Font Style Matcher 로, 목표 교체 순간 CLS ≤ 0.02 |
| 형식 | woff2 만. `fonts/*.otf` · 정적 `woff2` 10개(12MB) 삭제 |
| 예산 | 첫 화면 글꼴 전송 ≤ 300KB(현재 3.2MB 프리로드) — Pretendard CSS + 조각 + 세리프 CSS(gzip) + 세리프 조각을 모두 합한 값. 세리프 CSS 의 gzip 크기를 실측해 이 줄을 다시 적는다(확인 필요) |
| `<link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin>` | 34장 `<head>` |

### 4.0 서명 — 리포트 제호(masthead)

### 4.4 카드 vs 선

| 상황 | 쓰는 것 |
|---|---|
| 같은 형식이 반복되는 목록(리포트 목록·관심종목·브리핑 목록·최신 리포트) | **행(row)**: 1px `--hair` 구분, 세로 패딩 16px, 카드 아님(NN/g Cards: 동질 콘텐츠·비교에는 목록) |
| 서로 다른 종류의 위젯(홈 '오늘의 시장' 등) | 카드: `--bg-2` + 1px `--line`, 반지름 `--r-3`, 패딩 20px, **그림자 없음** |
| 떠 있는 것(드롭다운·팝오버·모달) | `--bg-2` + `--shadow-2/3`, 테두리 없음 |
| 표 | **상자에 넣지 않는다** — 열린 표(4.5): 위 1px `.12` 선 + 행 hairline + 아래 출처 줄, 외곽 테두리·반지름·배경 없음. 모바일 스크롤 래퍼는 배경·테두리 없는 `overflow-x:auto` 만 |
| 금지 | 카드 속 카드, 유리(`backdrop-filter`), 테두리+그림자 동시, 그라데이션 테두리·글로우, 높이 강제 통일, 호버 떠오름 |

## 8. 검사 가능한 규칙

사람이 기억하지 않아도 되게 한다. `check_all.sh` 의 '화면' 묶음에 붙이고, 헤더·팔레트·푸터처럼 **한 스크립트가 심고 `--check` 로 지키는** 방식을 그대로 쓴다. 단, `check_all.sh` 는 어떤 워크플로에서도 돌지 않는 **수동 검사**다(`.github/workflows` 참조 0) — 그래서 '어디서 도나' 열을 둔다. grep 검사의 대상은 34장 HTML + `r/index.html`·`r/005930.html` + JS 4종(`auth-guard.js`·`auth-state.js`·`settings-panel.js`·`consent.js`, 스테이징 포함) — JS 가 주입하는 CSS 는 HTML 만 보는 검사가 못 본다. v1 의 검사 정의 여섯 개가 코드 현실과 어긋나 곧바로 오탐했을 것이라(다크 `--fg-3` .56 vs '≥ .60', `backdrop-filter` 문자열 6회, 없는 `fadeIn`, `800` 오탐, h1 3개인 stock, v1 8절 리포트) 아래는 그것을 고친 정의다.

## 10. 미결 질문 (대표에게)

1. **기본 테마** — 라이트 기본(추천)인가, OS 설정을 따를 것인가. 랜딩도 라이트인가.
2. **세리프** — 마루 부리 / 본명조(Noto Serif KR) 동등 후보 / 세리프 없음. 'SK하이닉스 · LG에너지솔루션 · Samsung Electronics' 가 든 시안 세 장으로 정한다. 마루 부리를 고르면 네이버 라이선스 원문(수정·재배포 조항)과 fonts-archive 인용문의 대조를 누가 하나 — 불확실하면 자체 서브셋 또는 본명조.
3. **프리즘** — 히어로는 실제 리포트 화면으로 바꾸고 프리즘은 2D 브랜드 마크로 옮길지(추천), 무채색 3D 로 남길지. 남기면 스펙트럼 제거·8초 뒤 정지·정지 단추·인앱 정지 프레임에 동의하는지.
4. **다크 바탕** — 먹색 `#141414`(추천) / 지금의 남색.
5. **등락색 한·영 통일** — 영문 모드도 빨강 상승·파랑 하락으로(추천).
6. **강조색·링크 색** — 강조색 없음 + 먹색 밑줄 링크(추천, 파랑은 포커스 2곳에만) / 파랑 강조 유지. 브리핑의 종목 링크가 가장 큰 영향을 받는다.
7. **본문 17px**(추천) / 16px 유지.
8. **글꼴 CDN** — jsDelivr(추천, three.js 와 같은 곳) / 자체 호스팅.
9. **글리프 둘** — 음수 U+2212 · 빈값 U+2014 로 포매터 7곳을 한 번에 바꿔도 되는지(숫자 표기 뼈대에 닿는 유일한 변경).
