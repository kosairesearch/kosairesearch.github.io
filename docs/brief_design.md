# 모닝 브리핑 설계

날마다 한 편, 장 열기 전에 나가는 글. 이 문서는 **무엇을 쓸지**와 **그 값이 어디서 오는지**를 한 줄씩 맞춰 놓은 것이다. 값이 없으면 그 문장은 못 쓴다. 그래서 구조와 데이터를 따로 적지 않고 같이 적는다.

---

## 0. 전제

- **발행 시각 07:30 KST.** 미국장 마감(06:00 KST, 서머타임 05:00)과 국내 개장(09:00) 사이.
- **분량 2,500~3,000자.** 스크롤 두세 번.
- **휴장일에는 다른 글이 나간다.** 국내가 쉬는 날에도 미국은 열린다. 다음 개장일이 미국 몇 세션을 한꺼번에 반영해야 하는지가 그날의 핵심이 된다. → 휴장일 판정이 없으면 글의 전제가 틀린다. 실제로 8월 17일에 그렇게 틀렸다.
- **단정하지 않는다.** 종목 리포트와 같은 규칙. 저평가·고평가, 매수·매도, 목표주가 없음. 인과는 확인된 것만 쓴다.

### 남은 것 하나 — 해외 경제 일정

무료로 깔끔하게 긁을 데가 없다. `data/calendar.json` 에 **월 1회 사람이 열 줄** 적는 방식으로 간다.
FOMC 회의·의사록은 연준 사이트에서 자동으로 나오므로, 손으로 적는 건 잭슨홀·엔비디아 실적·
미국 지표 발표 같은 것뿐이다. 유료 캘린더 API(월 3~10만원)는 브리핑이 돈을 벌기 시작한
다음에 붙여도 늦지 않다.

### 만들면서 잡은 함정

앞으로 같은 실수를 반복하지 않기 위해 남긴다.

1. **휴장일** — 8월 15일 광복절이 토요일이라 17일이 대체공휴일인데 확인하지 않고
   '오늘 장을 준비하는 글'을 썼다. 대체공휴일은 달력 계산으로 안 나온다.
2. **단위** — 네이버 수급은 표에 따라 억원·백만원·원으로 온다. 백만원(3,038,700)을
   억원(30,387)으로 바꾸는 걸 틀리면 '외국인 303억 순매수'가 나간다. 사람이 검토해도
   지나치는 종류의 오류라서 자릿수 판정을 넣고 테스트로 못을 박았다.
3. **이중계산** — '기관계'는 기관 세부의 합계다. 둘을 같이 더하면 검증기가 정상 데이터를
   거부한다. 실제로 그래서 한 번 헛돌았다.
4. **컬럼 정렬** — 네이버 순매수 표는 11칸이고 기관 세부 여섯 개가 중간에 끼어 있다.
   헤더 이름만 골라 앞에서부터 짝지으면 금융투자 값이 '기관' 이름을 달고 나온다.
   이름이 아니라 자리로 맞춰야 한다.
5. **뉴스 숫자를 믿지 말 것** — 기사의 '필라델피아 반도체지수 roughly 1% 하락'을 그대로
   옮겼는데 실측은 −0.31% 였다. 숫자는 시세에서, 이유는 뉴스에서.
6. **레이트리밋** — 구글 뉴스는 1초 안에 여덟 번 때리면 503 을 준다. 간격과 재시도가 필요하다.
7. **캐시 위치** — Actions 러너는 실행마다 새로 만들어진다. `.gitignore` 된 폴더에 캐시를
   써 두면 다음 실행에 남지 않는다. `actions/cache` 로 실어야 한다.
8. **실패의 등급** — 뉴스가 없는 것과 개장 여부를 모르는 것은 다르다. 전자는 문장 하나가
   빠지고, 후자는 발행을 멈춰야 한다. 둘을 같은 실패로 취급하면 정작 봐야 할 것을 놓친다.

## 4. 데이터가 없을 때

브리핑은 어떤 값이 빠져도 **나가야 한다.** 값이 없으면 그 문장을 빼는 것으로 끝나고, 없는 값을 추측해 쓰지 않는다.

| 빠진 값 | 결과 |
|---------|------|
| 미국 지수 | 섹션 1 통째로 생략, 섹션 2로 시작 |
| 뉴스 | 숫자는 쓰되 "왜"는 쓰지 않는다. 인과를 지어내지 않는다 |
| 지수·수급 | 시총가중 등락률로 대체 (지금 방식) |
| 해외 일정 | 섹션 3에서 국내 일정만 |
| 휴장일 판정 | **발행 중단.** 이건 대체할 수 없다 |

## 5. 남은 일

수집은 끝났다(위 3절). 여기서부터가 남았다.

1. **확인 지점의 날짜화** — `checkpoints.when` 이 "8월 중", "10월 하순" 같은 자연어라서
   "이번 주에 걸린 것"을 자동으로 고를 수 없다. 리포트 생성 프롬프트에 `when_date` 를
   추가하고 다음 분기 재생성 때 같이 넣는다. 그때까지는 사람이 보고 고른다.
2. **`generate_brief.py`** — 위 데이터로 프롬프트를 채워 본문을 만든다. 섹션 1절 구조와
   4번 25% 상한을 프롬프트에 못으로 박는다.
3. **정적 페이지 렌더링** — `brief.html` 을 날짜별 `brief/YYYY-MM-DD.html` 로 굽고
   목록 페이지를 만든다.
4. **`morning_brief.yml`** — 06:00 / 06:40 / 07:20 KST 세 번 시도. 하나가 성공하면
   나머지는 건너뛴다(멱등 장치). 휴장일이면 다른 형식으로 쓰고, 개장 여부를 판정하지
   못하면 발행하지 않는다. `actions/cache` 로 공시 캐시를 실어 준다.
5. **알림** — 발행 성공/실패를 텔레그램으로. 조용히 안 나가는 게 최악이다.
