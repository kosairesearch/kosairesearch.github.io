# 모닝 브리핑 설계

날마다 한 편, 장 열기 전에 나가는 글. 이 문서는 **무엇을 쓸지**와 **그 값이 어디서 오는지**를 한 줄씩 맞춰 놓은 것이다. 값이 없으면 그 문장은 못 쓴다. 그래서 구조와 데이터를 따로 적지 않고 같이 적는다.

---

## 0. 전제

- **발행 시각 07:30 KST.** 미국장 마감(06:00 KST, 서머타임 05:00)과 국내 개장(09:00) 사이.
- **분량 2,500~3,000자.** 스크롤 두세 번.
- **휴장일에는 다른 글이 나간다.** 국내가 쉬는 날에도 미국은 열린다. 다음 개장일이 미국 몇 세션을 한꺼번에 반영해야 하는지가 그날의 핵심이 된다. → 휴장일 판정이 없으면 글의 전제가 틀린다. 실제로 8월 17일에 그렇게 틀렸다.
- **단정하지 않는다.** 종목 리포트와 같은 규칙. 저평가·고평가, 매수·매도, 목표주가 없음. 인과는 확인된 것만 쓴다.

### 만들면서 잡은 함정

앞으로 같은 실수를 반복하지 않기 위해 남긴다.

1. **휴장일** — 8월 15일 광복절이 토요일이라 17일이 대체공휴일인데 확인하지 않고
   '오늘 장을 준비하는 글'을 썼다. 대체공휴일은 달력 계산으로 안 나온다.
2. **단위** — 네이버 수급은 표에 따라 억원·백만원·원으로 온다. 백만원(3,038,700)을
   억원(30,387)으로 바꾸는 걸 틀리면 '외국인 303억 순매수'가 나간다. 사람이 검토해도
   지나치는 종류의 오류라서 자릿수 판정을 넣고 테스트로 못을 박았다.
3. **이중계산** — '기관계'는 기관 세부의 합계다. 둘을 같이 더하면 검증기가 정상 데이터를
   거부한다. 실제로 그래서 한 번 헛돌았다.
4. **컬럼 정렬** — 네이버 순매수 표는 11칸이고 기관 세부 여섯 개가 중간에 끼어 있다.
   헤더 이름만 골라 앞에서부터 짝지으면 금융투자 값이 '기관' 이름을 달고 나온다.
   이름이 아니라 자리로 맞춰야 한다.
5. **뉴스 숫자를 믿지 말 것** — 기사의 '필라델피아 반도체지수 roughly 1% 하락'을 그대로
   옮겼는데 실측은 −0.31% 였다. 숫자는 시세에서, 이유는 뉴스에서.
6. **레이트리밋** — 구글 뉴스는 1초 안에 여덟 번 때리면 503 을 준다. 간격과 재시도가 필요하다.
7. **캐시 위치** — Actions 러너는 실행마다 새로 만들어진다. `.gitignore` 된 폴더에 캐시를
   써 두면 다음 실행에 남지 않는다. `actions/cache` 로 실어야 한다.
8. **실패의 등급** — 뉴스가 없는 것과 개장 여부를 모르는 것은 다르다. 전자는 문장 하나가
   빠지고, 후자는 발행을 멈춰야 한다. 둘을 같은 실패로 취급하면 정작 봐야 할 것을 놓친다.

## 4. 데이터가 없을 때

브리핑은 어떤 값이 빠져도 **나가야 한다.** 값이 없으면 그 문장을 빼는 것으로 끝나고, 없는 값을 추측해 쓰지 않는다.

| 빠진 값 | 결과 |
|---------|------|
| 미국 지수 | 섹션 1 통째로 생략, 섹션 2로 시작 |
| 뉴스 | 숫자는 쓰되 "왜"는 쓰지 않는다. 인과를 지어내지 않는다 |
| 지수·수급 | 시총가중 등락률로 대체 (지금 방식) |
| 해외 일정 | 섹션 3에서 국내 일정만 |
| 휴장일 판정 | **발행 중단.** 이건 대체할 수 없다 |

## 5. 남은 일

수집은 끝났다(위 3절). 여기서부터가 남았다.

1. **확인 지점의 날짜화** — `checkpoints.when` 이 "8월 중", "10월 하순" 같은 자연어라서
   "이번 주에 걸린 것"을 자동으로 고를 수 없다. 리포트 생성 프롬프트에 `when_date` 를
   추가하고 다음 분기 재생성 때 같이 넣는다. 그때까지는 사람이 보고 고른다.
2. ~~**`generate_brief.py`**~~ — ✅ 6절 참조.
3. **정적 페이지 렌더링** — `brief.html` 을 날짜별 `brief/YYYY-MM-DD.html` 로 굽고
   목록 페이지를 만든다. `data/briefs/YYYY-MM-DD.json` 을 읽는다.
4. **`morning_brief.yml`** — 06:00 / 06:40 / 07:20 KST 세 번 시도. 하나가 성공하면
   나머지는 건너뛴다(멱등 장치). 휴장일이면 다른 형식으로 쓰고, 개장 여부를 판정하지
   못하면 발행하지 않는다. `actions/cache` 로 공시 캐시를 실어 준다.
5. **알림** — 발행 성공/실패를 텔레그램으로. 조용히 안 나가는 게 최악이다.

## 6. 생성 (`generate_brief.py`)

수집기가 만든 사실을 본문으로 바꾼다. 출력은 `data/briefs/YYYY-MM-DD.json` 이고,
3번(렌더링)이 그걸 읽는다.

### 모델과 호출 방식

| | 정한 것 | 왜 |
|---|---|---|
| 모델 | **Opus 5** (`claude-opus-5`) | 브리핑에서 값이 나가는 문장은 사실 나열이 아니라 연결이다 — 어느 숫자를 버리고 무엇을 제목으로 잡을지가 품질 전부다. 사용자가 품질 우선으로 정했다. Sonnet 5 와의 차이는 월 6,000원 정도 |
| 사고 | `thinking: {type: "adaptive"}` | 예산을 우리가 정할 근거가 없다 |
| 스트리밍 | 사용 | 양국어 3,000자면 출력이 길어 논스트리밍은 요청 타임아웃에 걸린다 |
| Batch API | **쓰지 않음** (`BRIEF_USE_BATCH=1` 로 켤 수 있음) | 아래 |
| 프롬프트 캐싱 | 쓰지 않음 | 캐시 TTL 이 5분/1시간인데 하루 한 번이라 언제나 만료다. 캐시 쓰기가 1.25배이므로 붙이면 손해 |

**배치를 왜 안 쓰나.** 50% 싸지만 비동기다 — 대부분 1시간 안에 끝나고 **최대 24시간**이며
한 건짜리 배치에 우선순위는 없다. 브리핑은 07:30 에 나가야 하니 그 꼬리에 걸리면 못 나간다.
아껴지는 돈은 월 5,000원인데, 4절의 원칙대로 조용히 안 나가는 게 최악이다.
그래도 쓸 수 있게 남겨 뒀다 — `BRIEF_USE_BATCH=1` 이면 배치로 내고 `BRIEF_BATCH_CUTOFF`
초(기본 40분) 안에 안 끝나면 취소하고 동기로 다시 부른다.

반대로 **리포트 생성은 배치가 맞다**(`generate_reports_batch.py`). 2,692종목을 한꺼번에
내고 마감이 없다 — 요청이 많고 지연이 상관없는 쪽이 배치가 값을 하는 형태다.

### 비용 (한 편당)

입력은 사실 블록이 대부분이고, 출력은 양국어 3,000자에 5,000토큰 안팎이다.
Opus 5 기준 하루 **$0.2~0.25 (약 300원)**, 월 1만원 수준. 아침에 세 번 시도하지만
성공한 뒤에는 같은 날 파일이 있으면 건너뛰므로(멱등) 과금은 하루 한 번이다.
`--dry-run` 이 `count_tokens` 로 실제 입력 토큰과 예상 비용을 찍는다(무료).

### 프롬프트에 못으로 박은 것

1절 구조(네 섹션, 순서 고정)와 **4번 25% 상한**. 그리고 함정 5번 — "숫자는 시세에서,
이유는 뉴스에서". 사실 블록에 뉴스 제목을 넘길 때 "제목 속 숫자는 쓰지 말 것"을 같이 적는다.

값이 없는 자리에는 **없다는 사실과 함께 무엇을 하지 말지**를 적어 넣는다.
"투자자별 순매수를 받지 못했다 — 외국인·기관 얘기를 쓰지 말 것" 같은 식이다.
4절의 저하 규칙이 프롬프트 안에서 실행된다.

종목 링크는 모델이 HTML 을 쓰지 않게 `[현대차](005380)` 형식만 허용하고, 코드가 여섯
자리이고 커버리지에 있는지 확인한 뒤 통과시킨다. 확인되지 않은 것은 평문으로 되돌린다 —
우리가 만들지 않은 링크가 페이지에 걸리는 경로를 여기서 끊는다.

### 나가기 전에 거부하는 것

`validate()` 가 보는 것: 분량(2,200~3,600자, 목표 2,500~3,000), **커버리지 비중**,
금지 표현(한국어·영어 양쪽), 섹션 id 와 순서, 문단마다 영문이 있는지.

거부되면 이유를 그대로 붙여 한 번 더 부른다. 두 번째도 실패하면 **발행하지 않고**
`data/briefs/_rejected/` 에 남긴다. 대충 고쳐 내보내지 않는다.
커버리지 상한은 1차에서 25%, 2차에서 30%까지 눈감아 준다 — 그 위는 발행하지 않는다.

`scripts/test_brief_gen.py` 가 이 검증을 네트워크·키 없이 82개 항목으로 고정한다.
특히 **'순매수'는 통과하고 '매수 추천'은 거부**되는 경계 — 여기를 과하게 잡으면 브리핑을
아예 못 쓰고, 느슨하게 잡으면 투자권유가 나간다. 영문도 같이 막는다. 한국어만 막아 두면
화면을 영어로 바꿨을 때 `price target` 이 그대로 보인다.

### 확인 방법

```
python3 scripts/test_brief_gen.py                   # 검증기 회귀 (무료·오프라인)
python3 scripts/generate_brief.py --facts-only      # 모델에게 넘길 사실 블록 (무료)
python3 scripts/generate_brief.py --dry-run         # 프롬프트 + 입력 토큰 + 예상 비용 (무료)
python3 scripts/generate_brief.py                   # 실제 생성 (과금)
```

앞의 셋은 과금이 없다. 드라이런 워크플로에도 ⑥⑦로 넣어 뒀다.
