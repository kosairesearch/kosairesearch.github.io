# 모닝 브리핑 설계

날마다 한 편, 장 열기 전에 나가는 글. 이 문서는 **무엇을 쓸지**와 **그 값이 어디서 오는지**를 한 줄씩 맞춰 놓은 것이다. 값이 없으면 그 문장은 못 쓴다. 그래서 구조와 데이터를 따로 적지 않고 같이 적는다.

---

## 0. 전제

- **발행 시각 07:30 KST.** 미국장 마감(06:00 KST, 서머타임 05:00)과 국내 개장(09:00) 사이.
- **분량 2,500~3,000자.** 스크롤 두세 번.
- **휴장일에는 다른 글이 나간다.** 국내가 쉬는 날에도 미국은 열린다. 다음 개장일이 미국 몇 세션을 한꺼번에 반영해야 하는지가 그날의 핵심이 된다. → 휴장일 판정이 없으면 글의 전제가 틀린다. 실제로 8월 17일에 그렇게 틀렸다.
- **단정하지 않는다.** 종목 리포트와 같은 규칙. 저평가·고평가, 매수·매도, 목표주가 없음. 인과는 확인된 것만 쓴다.

## 1. 섹션 구조

| # | 섹션 | 무엇을 쓰나 | 분량 |
|---|------|------------|------|
| 0 | 머리 | 날짜 · 제목 · 두 문장 리드 · 기준일 표시 | 150자 |
| 1 | 간밤 뉴욕 | 미국 3대 지수 + 반도체 지수, 움직인 이유, 국내로 옮겨붙을 성격인지 | 700자 |
| 2 | 직전 국내 장 | 지수·수급, 폭(중앙값 vs 시총가중), 업종, 거래 쏠림 | 650자 |
| 3 | 오늘/다음 개장까지 볼 것 | 환율·금리, 오늘 일정, 이번 주 일정 | 700자 |
| 4 | 코사이 커버리지에서 | 커버 종목에 걸린 확인 지점 중 이번 주에 결과가 나오는 것 | 600자 |
| 5 | 면책 | 고정 문구 | 100자 |

## 2. 섹션별 필요 데이터

### 섹션 1 — 간밤 뉴욕

| 값 | 소스 | 상태 |
|----|------|------|
| S&P500 · 나스닥 · 다우 종가/등락률 | Stooq CSV (`^spx` `^ndq` `^dji`) | 🔧 코드 필요 |
| 필라델피아 반도체지수(SOX) | Stooq (`^sox`) | 🔧 코드 필요 |
| 미 10년물 금리 | Stooq (`10ustby`) 또는 FRED | 🔧 코드 필요 |
| WTI · 달러인덱스 | Stooq (`cl.f` `dx.f`) | 🔧 코드 필요 |
| **왜 움직였나 (지표·개별종목 뉴스)** | 뉴스 검색 | ⚠️ **아래 3-③ 참고** |

지수 숫자만으로는 "S&P가 0.17% 내렸다"까지밖에 못 쓴다. **"미시간대 소비자심리가 예상을 밑돌아서"는 뉴스가 있어야 나온다.** 이 섹션의 값어치 대부분이 여기 걸려 있다.

### 섹션 2 — 직전 국내 장

| 값 | 소스 | 상태 |
|----|------|------|
| 전 종목 등락·거래대금·시총·업종 | `data/stocks.js` (`collect_data.py`) | ✅ 있음 |
| 등락 종목 수, 중앙값, 시총가중 등락률 | `brief_data.py` `breadth()` | ✅ 있음 |
| 업종별 등락 | `brief_data.py` `sector_moves()` | ✅ 있음 |
| 거래대금 상위 | `data/stocks.js` | ✅ 있음 |
| **코스피/코스닥 지수 종가·등락** | pykrx `get_index_ohlcv` | 🔧 코드 필요 |
| **외국인/기관 순매수** | pykrx `get_market_trading_value_by_investor` | 🔧 코드 필요 |

지수와 수급이 지금 빠져 있다. 8월 17일 초안에 "코스피 6,977"이 없었던 이유다. pykrx는 이미 `requirements.txt`에 있고 키가 필요 없다.

### 섹션 3 — 볼 것

| 값 | 소스 | 상태 |
|----|------|------|
| 원/달러 환율 | Stooq (`usdkrw`) 또는 한국은행 ECOS | 🔧 코드 필요 |
| **국내 휴장일 판정** | pykrx 영업일 조회 | 🔧 **최우선** |
| 국내 실적발표·배당기준일·주총 | DART 공시 + 리포트 checkpoints | ✅ 있음 |
| **미국 지표 발표 일정** (CPI, PMI, 소매판매…) | — | ❌ **없음** |
| **FOMC 일정·의사록 공개일** | federalreserve.gov 연간 일정 | 🔧 코드 필요 (연 8회 고정) |
| **잭슨홀 등 이벤트** | — | ❌ **없음** |
| **미국 기업 실적 일정** (엔비디아 등) | — | ❌ **없음** |

### 섹션 4 — 커버리지

| 값 | 소스 | 상태 |
|----|------|------|
| 리포트 본문·확인 지점(checkpoints) | `data/reports_v2/*.json` | ✅ 있음 |
| 신규 공시 감지 | `check_filings.py` | ✅ 있음 |
| 확인 지점의 날짜 파싱 ("8월 20일" → 20260820) | — | 🔧 코드 필요 |

지금 checkpoints의 `when`은 "8월 중", "10월 하순" 같은 **자연어**다. "이번 주에 걸린 것"을 자동으로 고르려면 이걸 날짜로 바꿔야 한다. 리포트 생성 프롬프트에 `when_date` 필드를 추가하는 게 제일 깔끔하다 — 다음 분기 재생성 때 같이 넣으면 된다.

## 3. 그래서 뭐가 필요한가

### ① 내가 코드만 짜면 되는 것 — 사용자 할 일 없음, 무료

1. **휴장일 판정** (pykrx) ← 최우선. 없으면 오늘 같은 사고가 반복된다.
2. **코스피/코스닥 지수 + 외국인·기관 수급** (pykrx)
3. **미국 지수·환율·금리·유가** (Stooq CSV, 키 불필요)
4. **FOMC 일정** (연준 페이지, 연 8회 고정이라 사실상 하드코딩)

→ 다만 3번은 **Stooq가 Actions에서 실제로 되는지 확인이 안 됐다.** `probe_sources.yml`을 한 번 돌리면 판정된다.

### ② 사용자가 발급받아야 하는 것

| 무엇 | 왜 | 비용 | 지금 |
|------|-----|------|------|
| **네이버 검색 API** | "왜 움직였나" — 섹션 1·2의 핵심 | 무료 | 사업자등록증 대기 중 |
| 한국은행 ECOS 키 | 환율·국고채 원본. Stooq가 되면 불필요 | 무료 | 미발급 |
| FRED 키 | 미 금리 원본. Stooq가 되면 불필요 | 무료 | 미발급 |

**ECOS와 FRED는 Stooq 판정 결과를 보고 정하자.** Stooq가 되면 안 받아도 된다.

### ③ 진짜 공백 — 뉴스와 해외 일정

이게 유일하게 "돈이나 사람 손"이 드는 부분이다. 정직하게 말하면 이 둘 없이는 브리핑이 **숫자 나열**에서 멈춘다.

**뉴스 ("왜 움직였나")**

- 국내: 네이버 검색 API. 무료. 사업자등록증 나오면 끝.
- 해외: 구글 뉴스 RSS가 영어로는 된다(`news_alert.py`가 이미 씀). 미국 지표·개별종목은 이걸로 충분할 가능성이 높다. → probe로 판정.

**해외 경제 일정**

무료로 깔끔하게 가져올 방법이 없다. 세 가지 선택지:

| 방법 | 품질 | 비용 | 손이 가나 |
|------|------|------|-----------|
| **A. 월 1회 수동 등록** — `data/calendar.json`에 그달 일정을 사람이 적어 둠 | 높음 | 0원 | 월 30분 |
| B. Trading Economics / FMP 유료 API | 높음 | 월 3~10만원 | 없음 |
| C. 스크래핑 (Investing.com 등) | 중간 | 0원 | 깨질 때마다 수리 · 이용약관 위험 |

**A를 권한다.** FOMC·잭슨홀·CPI·엔비디아 실적 같은 건 한 달에 열 줄이면 끝난다. 매일 자동인데 월 30분이면 싼 값이고, 유료 API를 붙이는 건 브리핑이 돈을 벌기 시작한 다음에 해도 늦지 않다.

## 4. 데이터가 없을 때

브리핑은 어떤 값이 빠져도 **나가야 한다.** 값이 없으면 그 문장을 빼는 것으로 끝나고, 없는 값을 추측해 쓰지 않는다.

| 빠진 값 | 결과 |
|---------|------|
| 미국 지수 | 섹션 1 통째로 생략, 섹션 2로 시작 |
| 뉴스 | 숫자는 쓰되 "왜"는 쓰지 않는다. 인과를 지어내지 않는다 |
| 지수·수급 | 시총가중 등락률로 대체 (지금 방식) |
| 해외 일정 | 섹션 3에서 국내 일정만 |
| 휴장일 판정 | **발행 중단.** 이건 대체할 수 없다 |

## 5. 순서

1. `probe_sources.yml` 한 번 실행 → 되는 소스 확정 ← **여기부터**
2. 휴장일 판정을 `brief_data.py`에 넣는다
3. 지수·수급(pykrx) + 해외 지수(Stooq) 수집 추가
4. `data/calendar.json` 만들고 8~9월 일정 채우기
5. `generate_brief.py` — 위 데이터로 프롬프트를 채워 본문 생성
6. 정적 페이지 렌더링 (`brief.html` → 날짜별 `brief/YYYY-MM-DD.html`)
7. `morning_brief.yml` — 06:00 / 06:40 / 07:20 KST 세 번 시도, 하나만 성공하면 나머지 건너뜀
